# Z7 campaign save boundary probe

This opt-in HOST diagnostic takes a user-supplied genuine Z7 predecessor SRAM image. It does not generate, modify or commit that private input. A temporary source view in a fresh ignored directory wraps selected existing `return 0` sites with stderr traces while preserving source line numbers and every condition. The original production code and guards are not modified. The fixture checks the seed's expected envelope, verifies that it is excluded by the tested candidate's accepted tags and exceeds its scratch capacity, checks the load refusal, starts a real Z7 campaign and checks save refusal. It verifies that neither call changes SRAM. This is a baseline rejection witness, not a desired final behavior.

With candidate engine `9d87a539` and the genuine predecessor image SHA-256 `182407d91e782c4e879e65047223a70a0ec5f83bbec0131d4e205debddbd0d39`, the record has outer tag `0x56435a54`, payload length 16,312 and sequence 1. The staged Z7-derived candidate accepts `0x77435a56`, `0x76435a56`, `0x36435a56`, `0x6c435a56`; its selector scratch capacity is 14,632 bytes. The record therefore fails both tag and capacity filtering before the prepare callback. `race_load_game` returns at `race_save_adapter.h:4360`; this explains the observed frontend rejection but is not a complete legacy migration. A fresh live Z7 save returns at the explicit `!race_mode` gate at line 1657. Both leave SRAM unchanged. Conditions and line numbers refer to that source revision, and test flags match the staged Z7 vector except for dropping its required non-HOST-only qualification flag.

Never retag or truncate a record to pass this test. A complete solution must authenticate and decode the predecessor product and codec with its exact bounds, migrate into detached candidate storage, validate context and actor semantics, and preserve the existing two-slot atomic selection and fallback rules. This probe does not claim all-campaign support, actual guest continuation or a qualified new save format.

Run only with the global native build flock and the normal free-space guard, for example using top-level `Makefile`, `tests/sc64-arm-qualification/Makefile`, this Makefile, `campaign-save-boundary`, a fresh `BOUNDARY_DIAG_ROOT`, and `BOUNDARY_SEED` pointing to the independently verified image. The test needs the same private generated Z7 profile inputs as the staged vector.

## Exact-producer metadata slice

The retained prefix was produced by source commit `f0dc1929629c44b9156d8127d5b23ed65ed7b0d1`, tree `529f628ac6ae12849d5dbb4242fd7fa30f2bc8ba`, with `baseline.argv.json` SHA-256 `3019c4b4b9c2e1000a13e70bee60666398008e0f4a0e97cbd870f4fe53f67fbf`. `run-producer-layout.py` checks the frozen source revision, argv and recorded input manifest (418 inputs) before building its witness with that vector. The exact producer reports `RaceSave` 16,296 bytes, 240 unit rows of 35 bytes at offset 4, 160 building rows of 28 bytes at offset 8,404, state at 15,652 and campaign mission byte at 15,954. It asserts these facts at compile time. The genuine journal is a 16,312-byte no-impact-extension payload, including the 16-byte transport trailer. The file contains private gameplay state and is not distributed.

`sc64_z7_legacy_envelope_probe.h` is a staged, **unwired metadata probe**. It checks a complete 16-KiB slot's bounded outer tag/length, nonzero sequence and FNV checksum; checks the exact old inner version, campaign/Zerg/mission fields, any IMP1 extension's structural bounds, and calls a trusted map-authority callback only for the expected map pointer. It exposes the observed envelope only, never actor decode, world installation, selection or a claim that a paid identity is valid. The game-context fixture calls it against the actual immutable Z7 descriptor via `race_z7_save_map_valid` and rejects a different map pointer. Checksums and tag matching establish the selected format and basic integrity; they are not cryptographic authenticity or proof of payment. A caller must revalidate the selected slot against mutation before commit.

The standalone ASan/UBSan fixture tests the genuine predecessor plus wrong outer or inner version, truncated/oversized lengths, checksum and sequence errors, malformed extension, custom/wrong-race/wrong-mission contexts, wrong map and aliased output; it verifies the input remains unchanged. It deliberately shows that a recomputed checksum with modified actor bytes can still pass this *metadata-only* check: actor identity and row validity are not yet implemented and this result must never authorize installing the world. Existing campaign save and load gates remain untouched. No live path references this header.

For a future bounded migration, the current Z/P route scratch is 32,768 bytes and the observed candidate record capacity is 14,632 bytes. A maximum-size legacy slot payload of 16,368 bytes and that candidate total 31,000 bytes before any extra state, so a two-region overlay is a plausible *layout to verify*, not a completed or qualified decoder. The current `race_impact_record` and `race_data` aliases start at the union's beginning, and the existing selected-record callback expects that address. Refactoring these aliases/selection, old compact-to-derived row conversion, authenticated source-versus-paid actor identity, impacted event/trailer validation, half-range sequence fallback, EWRAM/IWRAM/stack and all-product checks remain open. Do not point the existing selector at the larger record, relax the capacity or infer actor identity from this probe.

## Detached row and commitment probes

`sc64_z7_legacy_rows_probe.h` is explicitly HOST/probe-only and is not included by any live save path. After rechecking the metadata and trusted Z7 map, it reads one frozen v36 35-byte unit or 28-byte building row into local storage, invokes the existing feature-zero packed decoder, and applies the corresponding Z7 per-row source/type/owner checks. It does not install a world or replace the full Z7 source-row census, trigger, resource, queue, collision, mineral/geyser, transport, save-selection or transactional checks. Its transport probe decodes the four custom transport trailer jobs and requires them empty for this historical campaign context; it does not qualify other campaign transport state.

Under ASan/UBSan the genuine predecessor's 240 unit rows and 160 building rows decoded and passed these per-row checks (217 live units, no Egg in this one sample). All 240 units and 160 buildings were accepted by the current derived *encoders*, and the sample's live unit `weapon` fields were zero; this is not a complete semantic roundtrip or proof about other saves. In particular, derived rows intentionally omit some old fields, so later migration must establish their semantics and reject or represent every meaningful value rather than silently losing them. Rechecks reject stale checksums, recomputed-checksum wrong raw type or source-owner rows, and staged Scarab/Cocoon type retags in a feature-zero record without changing input or output. An old-codec Overlord/raw-36 row stays an Overlord through structural decoding; the original Z7 mission's Egg-specific rule rejects that synthetic row in this particular context. This must not be generalized into treating raw-36 Overlords as Eggs in custom or other profiles.

The optional commitment census validates the Z7 persistent-state structure, reads source rows in bounded loops, and reports occupied slots, paired-Egg extra bodies, queued products and the existing Z7 source-trigger create count. On the genuine sample these were 217 live, 23 free, zero queued, zero Egg extras and zero scripted creates. Synthetic paid-Egg-shaped rows demonstrate one reserved extra body per paired Egg, and a 12-Egg overcommit is **reported rather than classified as corrupt**. This is a census, not evidence the synthetic jobs were paid or a policy for continuing an actual overcommitted predecessor. The existing Z7 source trigger helper reports no Create Unit actions, but the probe does not establish the global mission-state relationships or the obligations of other missions, Carrier/Scarab services or future Guardian/Hive/Spire morph jobs. A complete migration must preserve all legitimate pending jobs, wait safely where appropriate, and validate the entire world before committing.

Each row operation currently rechecks the full envelope and map; this is deliberately conservative and HOST-only, not an acceptable unmeasured guest implementation. A later bounded snapshot/streaming design must avoid time-of-check/time-of-use races, establish source-created versus paid identities, account for all reservations exactly once, test legacy/raw-36 cases across modes, and requalify RAM, stack and timing without weakening existing limits.

The HOST-only row projection prototype performs a per-row source/identity and commitment census, then requires every v36 row to roundtrip exactly through the derived codec before writing a detached 10,988-byte row image. Its validity bit is cleared on a failed attempt and set only after final source recheck. It leaves SRAM and the live world untouched; if the source changes during its second pass, partial scratch contents are invalid. It is not a selected record, a complete `RaceSave`, or a load admission. The sample's 240/240 units and 160/160 buildings roundtripped byte-for-byte, with 217 live units and no live old Battlecruiser. Synthetic tests reject a nonzero legacy weapon field and a noncanonical building maximum instead of silently losing them, reject resealed actor/source retags, and project synthetic paired Eggs even when the census reports an overcommit. The latter only preserves row-level evidence: it does not prove the jobs were legitimately paid or that continuation is safe.

The candidate `RaceSave` is 14,416 bytes: the rows and common tail are shifted 1,920 bytes earlier than the exact v36 layout, and 40 bytes of candidate Battlecruiser shot state are appended. The predecessor producer did not enable the candidate's Battlecruiser experiments; its sample has `state[27]==0`, while the current candidate's selected-record path requires the newer BC signature. Migrating older BC actor/energy/research/shot semantics and the old cargo representation must be independently designed and validated; simply changing a tag, zeroing fields, or adding the signature is not sufficient. The row projection plus maximum old payload fits within 32 KiB as a size exercise, but it does not coexist with a separate complete candidate `RaceImpactRecord`; actual overlay lifetimes and selection fallback remain unproved.

A subsequent HOST-only fixture assembled a separate, detached candidate from the verified v36 common tail and the losslessly projected rows, retained the exact old inner version, and bound a test-only feature-zero tag pair matching the old outer/inner values. The existing `race_z7_save_candidate_valid_for` accepted this genuine sample; an encoder-representable forged source identity was rejected, and both validator calls left the candidate unchanged. This demonstrates the Z7 mission validator boundary only. It does not call the actual selected-record prepare/full load preflight, does not install the world, does not migrate or synthesize the BC signature, and uses additional HOST test storage rather than a qualified guest scratch layout. The old source slot was unchanged. Full actor provenance, source-created Cocoon versus paid morph, other missions/codecs, BC compatibility, two-slot arbitration and all runtime limits remain open.
