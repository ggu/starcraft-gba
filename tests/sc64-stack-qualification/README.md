# Experimental ARM system-stack paint

This opt-in diagnostic targets the staged shared-actor Z7 ARM profile. The `SC64_ARM_STACK_PAINT_QUALIFICATION` macro is rejected for HOST and without `SC64_SHARED_ACTOR_ARM_QUALIFICATION`. It paints unused system-stack words before `gba_init`, only when IME is zero and the observed SP is in range. The interval is `[0x03005000, observed SP - 512)`, with marker `0xa55a3cc3`. It publishes the sampled SP, end and status in EWRAM; it never paints the IRQ/BIOS band. Linker reserve guards, actor limits and normal product flags are unchanged. Read the actual compiled disassembly before running a new build: verify that the painter's prologue and caller leave the written range below live frames and that initialization has not enabled interrupts.

`custom.py` drives the existing physical-input custom-game continuation and samples the paint with read-only IWRAM reads at its state checkpoints. It compares actual pause-menu SRAM save and a fresh-process HOME-L load via the continuation tool's scoped fingerprints. `legacy.py` first authenticates an independently retained Z7 prefix with the existing checksum/schema verifier, then attempts ordinary HOME-L and, if loaded, an ordinary pause-menu campaign save; it records the save refusal and compares exported SRAM with the unchanged seed. `campaign.py` launches Z7 with ordinary buttons using the actual custom SRAM produced by `custom.py`, verifies the campaign-save failure notice, and checks that the seeded journal remains byte-identical. All three take explicit ROM, ELF and physical backend paths and create new output directories. They do not write guest world state or synthesize a journal. Both must run under the shared native lock with sufficient disk reserve. `custom.py` records exact step calls for candidate/diagnostic comparison; compare those, selected state fingerprints, outcomes and genuine SRAM separately.

The sampled untouched bytes measure only a region of one instrumented build on the driven path. The live-frame gap, stack use before paint, IRQ and BIOS stack, stack allocations without writes, overwritten-then-restored markers, other paths, and physical hardware remain outside this result. Instrumentation changes code and data placement. Compare against the exact noninstrumented candidate and keep paired checks and all build/input hashes. A positive untouched count is not a complete stack bound or a release qualification.

`Makefile` must be included after `tests/sc64-arm-qualification/Makefile` alongside the top-level Makefile; `stackq-z7` builds only the diagnostic. The actual candidate uses the same ARMQ and product flags without this paint macro. The executable and private generated art, ROMs, SRAM, backend and logs remain ignored local artifacts.
