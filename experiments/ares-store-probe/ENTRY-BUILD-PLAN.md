# Two-entry caller probe: proposed build and limits

This is an unbuilt source candidate. The copied core patch retains the existing post-write callback and adds guest RA and a0–a3 arguments to the interpreter begin callback, directly from `ipu.r[31]` and `ipu.r[4..7]` before `decoderEXECUTE`. The recorder emits entries only for sign-extended PCs `ffffffff8000c390` and `ffffffff80122904`, only after the existing full 8 MiB baseline hash and actor identity checks arm the store probe. The existing store event protocol is retained. Entry records are 56 bytes, capped at 1,024; 4,096 48-byte store records plus 1,024 entry records occupy at most 253,952 bytes total, below the existing combined 256 KiB allowance. Overflow or zero events fails the entry role. The same 4,322-step plan, three 8 MiB views, two frames, Metal-compatible 8 MiB file limit, 63/64 MiB owned output, 175/180 seconds, 5 GiB reserve and global lock are unchanged.

The interpreter's actual PC/opcode, RA and argument registers are captured at prologue; no extra guest read or mutation is performed. Guest RA equal to `ffffffff8013b418` or `ffffffff8000c550` at the first entry is consistent with the respective static JAL call sites including their delay slot; RA equal to `ffffffff80008b18` or `ffffffff80139b30` at the second is consistent with its respective candidates. Entry events alone do not prove update dispatch, independent clock, STOP or a second actor.

Proposed build starts from the same clean pinned ares revision and exact 12 admitted upstream input hashes. The tracked `ares-core-patch.txt`, changed `store_hook.h`, `store_recorder.h`, observer C++ and added `hybrid_entry_events.py` form new source inputs. `prepare_copy.py` admits the patch SHA and original CPU/memory hashes, copying without hardlinks. Reuse the prior bounded recipe structure: pin CMake flags/build/link metadata; compile only copied `ares/n64/cpu/cpu.cpp` with original flags plus `SC64_OBSERVER_CPU_STORE`; capture pre/post CPU and observer compiler include closures, reject original source paths, and verify generated/source hashes; copy the original archive, assert the unique `cpu.cpp.o`, replace it and rerun ranlib, requiring every other code member unchanged while recording the regenerated symbol index. Link a separate observer and pin its new binary only after tests and review. Use 256 MiB per-file, 600 seconds per command, 5 GiB and the shared lock. Source copy is about 44 MiB, CPU object about 8.2 MiB, archive about 168 MiB; compile duration is not predicted.

Asset-free fixtures include the actual patched prologue/decoder/end text extracted from the copied CPU file and exercised with stub CPU/register state; this tests call ordering and supplied RA but does not emulate a MIPS JAL delay slot. Separate recorder tests check both allowlisted PCs, argument values, 1,024-entry overflow and RA examples. Existing extracted patched `CPU::write` tests cover translated-failure and cached/direct callback behavior. A real linked-core equivalence and independently controlled MIPS delay-slot fixture remain required before attributing native calls. No core build or native replay has been performed or authorized by this source plan.
