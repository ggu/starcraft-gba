# Experimental interactive callback bridge

This separate, uncompiled and untested prototype keeps a fresh emulator process for bounded ordinary controller chunks. It is not yet qualified for reference evidence. Configure a separate isolated build using `interactive.cpp` as `SC64_PROBE_SOURCE`, and review both files before testing. The existing scripted frontend is unchanged.

`interactive.py` checks the pinned source, owned ROM and exact MoltenVK library, holds the common native lock, requires 5 GiB free and bounds the child at 180 seconds. It copies the ROM and isolates the output/saves. The child accepts one ASCII line per command: `steps mask x y capture`, with 1–1000 steps per command, 9000 total, 30 seconds per line and 60 seconds cumulative input wait. Mask bits: A=1, Start=2, Down=4, C-Left=8, Right=16; axes are signed -32767…32767. Capture 1 requests one callback copy, capture 0 advances without storing a frame. Responses are READY, OK, NOFRAME or FRAME; frame observations are asynchronous and are not exact game-update timestamps. It retains command, input and callback records, at most 32 images and 64 MiB of copied pixels. EOF or timeout ends the session; no savestate, guest memory or host event API is used.

The bridge has not been compiled or exercised. The 30-second command and 60-second cumulative idle caps require a responsive visual supervisor. An outer 180-second kill is the hard bound if the core blocks inside a chunk. The first qualification should use short neutral chunks and confirm output, timeout behavior, fresh save isolation and input logs before attempting a mission. No audio is retained.
