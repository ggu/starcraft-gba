# Shared Scarab integration map

This is a source map for a future adapter on shared runtime `64047b1`, not an enabled service or a completed save design. The Reaver skirmish admission gate remains in `starcraft/sc64_skirmish_adapter.h`. A Scarab needs its own identity and phases; an Interceptor's flags, target meaning and flight rules are not interchangeable.

## Actor lifecycle and world participation

- Allocate a real child only when a paid queue entry starts. `game.c` unit creation around `find_unit_slot()` (near line 2120) clears per-slot facing, projectile, impact and Carrier references before reuse. Add Scarab reference invalidation there and on all child retirement paths; reject a reused slot unless parent, owner and phase match.
- Training and completed-inside children must not run generic orders or participate in the map. `game.c` builds owner lists around 7092 and runs unit orders around 7128; `sc64_targets.h` builds the fallback target index around 130–138. Filter hidden Scarabs from both list construction paths. Active children need their own tick before generic order processing, not `SC64_CARRIER_CHILD_SCRIPTED` as-is.
- Apply the same hidden predicate to both persistent and legacy collision bucket construction and fallback scans (`sc64_collision.h`, `sc64_collision_legacy.h`, and `game.c` unit-step fallback around 2921). Launched Scarabs have a *temporary* source no-collision phase, not permanent immunity; changes to eligibility during a tick must update/invalidate collision and target indices.
- Visibility source accounting (`sc64_visibility.h` around 858), unit drawing (`game.c:8913`), minimap (`game.c` around 9353), selection/hit testing (`game.c` around 3704–3846 and `field_controls.h`), targeting and damage eligibility (`game.c` around 3543, 3704 and 4156) each have their own filters. Training/inside children must not reveal, render, select, be targeted or receive unrelated area effects. Do not assume the Carrier macro covers all of these paths; several test only `SC64_TRANSPORT_LOADED`.
- Unit allocation and counts, owner supply, AI rosters and skirmish victory/census must distinguish hidden ammunition from ordinary combatants. Explicitly audit `race_adapter.h`, `skirmish_adapter.h`, `race_skirmish_ai.h`, and generic alive/owner loops before exposing production. Child raw/type mapping and canonical actor facts must exist in each enabled build.

## Stop, destruction and transfer

- `game.c:5324` is the shared `stop_selected()` used by the menu (`game.c:5765`) and command ring (`command_ring.h:105`). It sets selected orders idle and clears `carry` and `target`. A deliberate Reaver STOP must order its outside child to self-destruct before these fields are cleared, while retaining its paid queue and inside children. Do not infer STOP from every transition to idle. Parent destruction, transfer, conversion, target removal and child expiration need separately specified transitions.
- Combat death in `hit_target_impl_ex()` (`game.c` around 4220–4280) invokes Carrier and transport cleanup before clearing `alive`. Add parent/child cleanup while identities still exist and remove target references. This is not the only removal route: source triggers and adapters directly clear `alive`, including `sc64_z5_world_adapter.h`, `sc64_p5_world_adapter.h`, `sc64_p6_world_adapter.h`, `sc64_z6_world_adapter.h`, `sc64_t4_effects_adapter.h`, `sc64_t5_scenario_adapter.h`, storms and other mission adapters. A bounded reconciliation before child use/slot reuse, plus explicit hooks where immediate source semantics require them, must cover removals that bypass combat; this list is not an exhaustive proof of every path.
- Transport boarding, unloading and carrier destruction live in `sc64_transport_adapter.h` (especially the cargo predicates near 144 and destruction near 168). Hidden/active Scarabs must not be accepted as ordinary cargo, and loading or losing a Reaver must have an explicit rule for its active child and paid queue. Do not conflate the Reaver with a transport Carrier.

## Persistence constraints

The late Terran and Z/P runtime `Unit` layout (`game.c` around 879) already has `carry`, `build`, `work_timer`, `target`, `flags` and other fields. Reusing fields in parent/child slots could avoid new persistent BSS, but **no zero-BSS encoding is established yet**: generic orders, STOP, transport, death, morph, AI and renderer paths already mutate these fields. A proposal must specify type/phase ownership and show no collision with existing consumers on all four canonical profiles.

The intersection of existing compact codecs is restrictive: `sc64_p7_typed_unit_save.h` requires a canonical 6-bit type and reconstructed HP/armor, `cd` 0..255, `order` 0..15, `carry` −65536..65535, `build` −2..239, `work_timer` 0..2047, target −1 through the valid combined entity range, and flags 0..0x3fff. The Z/P packed codec (`sc64_zp_unit_save.h`) permits a wider `work_timer` and `build` but still has 6-bit type and four-bit order; the Terran compact codec (`sc64_compact_unit_save.h`) also validates bounded fields. The current order enum reserves 14 for pending construction and 15 for shared recharge, so a new persistent order value cannot be assumed free. Raw Scarab 85 is not currently a canonical `Unit` type: mapping, fact tables and P7 canonical reconstruction would need explicit support.

Validate the complete candidate save world before mutating live state: parent/owner identities, child phase and slot uniqueness, active build and paid queue, at most one outside child, timers, selected/hidden state, and slot reuse. An owner without the capacity upgrade can inherit an already over-capacity Reaver; prevent new queue admission rather than rejecting that state solely for exceeding the new owner's capacity. Define versioning and legacy migration or safe refusal, then test fresh-process SRAM for training, inside, flight, STOP, death and transfer on each codec. Keep the runtime service gated until the representation and these transitions are proven.
