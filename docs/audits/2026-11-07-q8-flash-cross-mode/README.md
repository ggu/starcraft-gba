# Flash Q8 cross-mode admission: source audit

The PR349 experiment admits only custom Protoss-human saves: the live writer and detached fraction scan both check that restriction. Its `0x48` Flash envelope uses the actual `0x45` custom active-job payload and the detached validator; it is not a general campaign format. The separately staged all-custom HOST flag uses a common roster predicate for the live and detached contexts. It requires the selected human to equal the saved/current SIDE race and each active bot selection to equal that controller's player race. Actor raw origin is not controller identity. The existing research scan still checks active Protoss controllers, payer and job receipts, levels, duplicates and legacy upgrade state; non-Protoss owners cannot gain typed levels by this change. Full game preflight, existing capacities, tags and alias checks remain. This untested flag does not enable any normal product.

The fraction field is not uniform. Q8 units and non-burning buildings use the detached sidecar; eligible Terran buildings use the low byte of `shield_remainder` as their authoritative HP debt, with upper bits retaining burn attribution, and must have zero duplicate sidecar debt. Stock shielded actors use phase units of 1/1280; non-shield fields may instead carry trap, burn or regeneration state. Legacy unit phase conversion follows the existing battery migration and is being qualified in the separate phase branch; it is not part of this source checkpoint. Z5 regeneration uses its own remaining phase and Q8 HP debt. Terran repair's existing worker `ORDER_REPAIR` reservation is refused by the experimental candidate until its producer/consumer and old-save semantics are qualified; fractional-only repair and colony morph must be checked in actual enabled service contexts. Never clear these aliases merely because the human chose another race: mixed custom rosters can have actors of all races.

Campaign is a separate boundary. The current scoped build forbids the campaign job flag, Flash write ownership rejects committed legacy `0x47`, and the custom `0x48` decoder dispatches the base as `0x45`. Campaign jobs have detached canonical mission/current-human policy and separate `0x47` provenance; actor raw source owner is not its current controller or payer. A campaign-capable envelope needs an explicitly inventoried noncolliding namespace and version that selects the actual `0x47` campaign decoder, supports eight owner research levels and validates mission roles, source policy, original payer and active jobs before publishing any world state. Preserve `0x43/44/45/47/48` readers and fallback, including checksum-valid semantically invalid newer records and immutable old bytes. A generic custom `0x45` reinterpretation of a `0x47` record is not migration. Source inventory currently reserves `0x43`, `0x44`, `0x45`, `0x47` and `0x48`, with `0x46` used by the separate journal experiment; any proposed new namespace requires a full current-source collision test, not just this list.

The HOST all-race fixture stages authored Terran and Zerg custom saves with fractional unit HP, a Terran burning-building debt, separate-process loads and invalid roster checks. It is not yet compiled or run. It uses the P10 product vector; it cannot qualify Terran/Z9 vector-specific storage, repair, Z5, old-format migration, malformed-newer fallback, all impacts, active Protoss AI jobs, campaigns, ordinary input, emulator or hardware. Before expansion, use genuine predecessor producers and fresh consumers, valid mixed-race jobs and wallets, malformed controller/payer/alias negatives with no mutation, maximum legal actor/impact/transport states, and all six guarded links. The previous Z9/Z10 EWRAM margin of 196 bytes predates the approximately 72-byte transaction state; remeasure from the final combined source and inspect aggregate stack call chains and runtime high-water rather than infer safety from individual `.su` frames.
