# Shared Flash composition: proposed version 1

This is a design for the default-off experiment, not an admitted save format. The existing custom 0x48 and P1 0x49 meanings and readers remain unchanged. A separately inventoried namespace is required for a shared compound record. A candidate namespace value of 0x4a is a proposal, not a reservation or proof that all external historical formats are known.

Use a fixed 32-byte little-endian envelope: four-byte magic; two-byte envelope version; one-byte product/profile and one-byte mode; two-byte mission and two zero reserved bytes; four-byte feature bitmap; four-byte base length; two-byte debt length, two-byte controller length, two-byte payer length and two zero reserved bytes; four-byte base-codec identifier. Sections follow in that order: the complete actual selected cargo/impact/transport base, per-actor HP debts, current controllers, then per-unit paid-Scarab payer witnesses. Offsets and sums require checked arithmetic. The outer journal checksum covers this entire payload. Reject unknown version, profile, mode, feature bits, codec, nonzero reserved fields, wrong exact section sizes, and trailing bytes. The envelope provides format and context validation, not cryptographic authenticity.

The initial proposed feature set is explicit Q8 debt, current controller and Scarab payer/flight support, with all four feature bits required in the first Z10 campaign implementation. Controller entries contain one byte for each unit followed by each building. Payer entries contain one byte per unit, with a canonical zero for non-Reavers; nonzero encodings must be bound to the detached current controller and an actual uniquely mapped source town, not raw origin. The base must continue to encode the real current cargo, impact, shot and campaign state; the codec identifier must distinguish its exact semantics rather than pretending a 0x47 research record is a Z10 record. Z10's 240 unit and 160 building capacities give 400 debt bytes, 400 controller bytes and 240 payer bytes. With the prior 16,368-byte current-journal payload bound, the conservative envelope total is at most 17,440 bytes, under the 28,656-byte Flash slot payload. This is a byte bound, not proof that every new mixed-feature base fits the older bound; enforce and measure the actual combined base length independently. No actor, impact or transport capacity is reduced.

A candidate load must first verify outer ownership, length and checksum, then parse the envelope into a detached, bounded context carrying the profile, exact codec and feature set. The existing cargo, campaign/map and impact validators must use that context to decode raw-85 flight rows without relying on a mutable global tag flag. Validate every child/parent relation, current-controller match, payer witness and in-flight target against the same candidate; reject unknown or ambiguous towns. Existing capture rules prohibit moving a paid parent or child while work remains. Old records are decoded only by their own prior readers; they cannot gain an inferred controller or paid child. Unsupported but committed records block writing a new epoch even when their checksums or lengths are malformed. Load fallback and no-write refusal must remain distinct.

The writer must build the real base and sidecars in bounded scratch, run the same detached full preflight before the first erase, restore normalized scratch on every exit, reselect and compare the complete descriptor plus content, and publish the commit tag last. Failed I/O, stale selection or semantic rejection must not publish live actors, wallets, controllers, debts or paid jobs. No second full payload buffer is required by this proposal, but actual stack and EWRAM bounds have not been measured. The existing 32 KiB legacy region remains read-only. The prior isolated row tests cover only training/inside layout; they do not establish actual selector composition or an outside-child save.

At P1 fixture source `b13deb13`, four additional authored HOST-model tests exercise the real game save/load path: selected-descriptor sequence change, a competing epoch change after selection, an initial save read error, and a controller-tail load read error. All returned failure without an erase/program callback or changes to saved device bytes beyond the test's explicit simulated external sequence change; unit/building arrays, controller arrays, HP debts, research levels, wallet and frame snapshots remained equal. The P1 producer suite passed at predecessor `d71c9528`, and source boundary passed at `b13deb13`; the intervening test-only change fixed a local variable shadowing the building array. These are not hardware, concurrent-device, or Z10 persistence results. Receipts and authored save images remain private ignored artifacts.

The first actual Z10 milestone still requires real paid training, inside and outside-child fresh-process saves and continuations; verified town-wallet and transfer behavior; malformed new records and predecessor fallback; complete ownership/fault handling; resource and stack measurements; and eventually guest and hardware qualification. No normal flag or save format has been enabled.
