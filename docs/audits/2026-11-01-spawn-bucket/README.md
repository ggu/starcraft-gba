# Spawned collision bucket membership

An actor created after `sc64_unit_buckets_begin()` could be missing from the active collision index until its first move, or a reused dead slot could remain in its old cell. A later actor could therefore move through it in the same update. `spawn_unit` now reconciles an in-bounds new actor through the existing bucket-move lifecycle before returning; an out-of-bounds birth disables the index so existing full-world fallback remains authoritative. The existing spawn and move memo invalidations apply. The helper uses the legacy or persistent implementation selected by the active profile; no mission predicate is widened.

At focused source `cf15896` against matched fixture-only baseline `55ae409`, ordinary `spawn_unit` was exercised for fresh and distant reused slots, followed by collision queries before the new actor moved. The independent oracle was `unit_step_clear_race_fallback`, the original full-world scan, not the bucket-backed reference. Baseline failed both cases in legacy and persistent profiles with contact memo off/on (eight expected failures at the intended mask comparison); the candidate passed all four corresponding variants, including bounds fallback and actual Dropship board/tick when shared transport was enabled. The optional Scarab-noncolliding case was not compiled in those vectors. ASan/UBSan fixture runs used the pinned prepared inputs, with pins and source verified before/after. This result is scoped to the focused vectors, not a physical campaign trajectory or native collision timing proof.

`test-sc64-spawn-index` is an optional prepared-input target with legacy/persistent and memo-off/on variants. It is not part of the clean default test suite and does not generate private inputs. Full profile builds, strict memory guards, ordinary mission replay and the Scarab-specific path remain to be qualified before admission. No N64 update-order or hardware FPS equivalence is claimed.
