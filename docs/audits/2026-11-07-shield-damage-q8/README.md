# Per-hit shield and armor arithmetic

This source-only helper is not wired into gameplay. It models the ordering in pinned OpenBW `bwgame.h` at revision `4b046d5f65302b10cb0a745f0fecd37ec85b20a8` (retained file SHA-256 `5ee316ca2c008c9252f7fde7444ca5dc7f35440549be2576dc37fa228fb31ae6`), especially `weapon_damage_amount` around 13463 and `weapon_deal_damage` around 13658–13709. This is a PC-source reference, not a claim of measured N64 behavior.

For each actual hit, callers provide the per-hit pre-armor Q8 packet including source-owner weapon upgrades. The helper doubles against a hallucinated target, divides for the splash tier, adds acid-spore damage, applies the half-point minimum, and removes defensive matrix first. With at least one full shield point, it subtracts the target owner's Plasma Shields level before absorption; a packet no larger than that armor becomes one half point. Armor-ignore damage bypasses both armor steps but still reaches shields. HP armor applies only to overflow, followed by explosive/concussive size scaling. If no shield damage occurred, HP damage has a half-point minimum. This is per hit: aggregating repeated hits first changes armor. `damage_type_none` still follows the source's shield ordering and final minimum branch. Invalid arguments and arithmetic overflow fail without modifying the output.

A target with less than one full Q8 shield point does not absorb a hit in this source implementation. The source checks shield armor after matrix even when matrix consumed the whole packet, so the normal-armor branch can still produce half a shield point of damage; the fixture preserves this specific ordering rather than silently changing it. The helper returns exact Q8 results and clamps HP loss to current HP. It does not choose targets, determine owner or upgrades, apply hit multiplicity, update live actors, or perform death/effect callbacks.

Existing engine state stores whole HP and shields. `shield_remainder` is a persisted 1/1280-point shield regeneration/battery phase where applicable, but it is also used for unrelated state such as Z5 HP regeneration, P6 trap cooldown and Terran building burn/source owner. No field is universally available for Q8 HP or shield fractions; this helper does not reinterpret or change any field or save tag. Integer quantization, including repeated half-damage retention, needs an independently reviewed storage policy before a runtime adapter can claim source-exact damage.

Ordinary `hit_target_impl_ex` currently performs integer shield absorption before HP armor. P6 explosive and P7 Archon adapters calculate damage before calling `hit_target`; Siege splash has a separate Q8-to-integer resolver; storm uses ignore-armor logic; bunker passengers and Carrier/Interceptor routes need their individual hit semantics checked at their actual dispatch sites. Integrating the helper twice would apply armor or shields twice. Any future adapter must assign each hit exactly one resolver, preserve shield/HP fractions and authenticated owner, and separately test all those routes and legacy saves.

The asset-free `test-sc64-shield-damage-q8` fixture uses manually calculated vectors for shield armor, overflow, half-shield threshold and minimum, matrix, ignore-armor, size scaling, hallucination/divisor/acid ordering, repeated hits and fail-closed overflow. It does not by itself qualify gameplay or hardware timing.
