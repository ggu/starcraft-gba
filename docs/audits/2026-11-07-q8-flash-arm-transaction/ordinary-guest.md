# Ordinary-input Flash save and fresh load

At runtime source `4724e8c7` and replay-adapter source `97555bf87001e69ead1884382185f862ea968c93`, an experimental P10 ROM used physical button events to reach a paid custom-game research job, pause and save, then loaded the exported Flash image in a fresh unforced mGBA process and continued until that job completed. Both processes logged guest-command Flash detection and 512 Kbit to 1 Mbit bank upgrade. The guest's save/load path used the actual game serializer and detached validation. No guest memory or registers were injected, no save records retagged, and no device type forced. The saved image was transferred as device backing, not as an emulator state.

At frame 3005, the paid job belonged to owner 0, family 3, with 4,999 ticks remaining; the wallet held 376 minerals and 12 gas and the level was zero. The ordinary pause-save preserved these values. After a fresh title load at frame 3006, the wallet was still 376/12, the job had 4,998 ticks remaining and the level was zero. At frame 8006 the job was gone, level index 2 was one, and the wallet held 928/668. These are named observations, not complete-world equivalence. The replay did not capture or assert the save UI notice; the valid record and fresh load are the save evidence.

The 128 KiB exported image retained all `0xff` in the first 32 KiB and the second new slot. The first new slot commit and metadata tags both read `0x7648505f`; length was 16,716, sequence one and stored and independently recomputed FNV were `0xed92e3fa`. FNV is an accidental-corruption check, not authentication. The blank input and replay inputs were verified unchanged by the supervisor. The source head and adapter hash were checked around preparation and after the run, not continuously during it.

The first guest attempt, before the corrected backing setup, reached the pause/save checkpoint but wrote no valid record. Its image had an erased first bank and a zero-filled second bank. In the pinned mGBA source, `_flashSwitchBank` initializes an expanded bank to `0xff` only when a backing VFile exists; the first attempt had none. The game correctly refused the resulting unknown non-erased layout. The corrected run attached a new, entirely erased 128 KiB in-memory writable VFile before boot. `GBASavedataMask` preserves the prior autodetect type; the guest's unlock and bank commands performed type detection and upgrade. The original blank file remained unchanged. The previous failed image and log remain private ignored artifacts. No polling delay or transport change was introduced between attempts.

The experimental ROM, at exactly 32 MiB, contains one `FLASH1M_V` signature and no `SRAM_V` signature. Preparation passed both ASan/UBSan callback and fake-register tests and the guarded P10 link, with 593 prepared input hashes unchanged. The ownership correction explicitly requires the audio initialization claim as well as matching register values; independent source review found it sufficient for current code, conditional on future DMA ownership handoffs clearing that claim. The result does not prove audio continuity, failure recovery, real Flash hardware behavior, Q8 fractional damage persistence, other profiles, or normal product enablement. The separately developed legacy shield-phase migration is not included in this branch.
