# N64 selected-Probe STOP control: admissibility

The original [StarCraft 64 manual](https://nintendo64.pl/wp-content/uploads/StarCraft-64-USA.pdf), printed pages 4–5 and 7, says that B directs selected units to attack or move to the cursor and that the contextual C-button commands appear on screen. It describes issuing Move but does not identify a STOP shortcut. The retained qualified selected-Probe image from the pause/resume control visibly offers BUILD, MOVE, BUILDADV and ATTACK; it does not show STOP. Therefore neither B nor any particular C button is established as STOP for this selected Probe. PC Stop behavior is not an N64 control mapping. No STOP command file is admitted on that basis.

The previously qualified observer can trace this one selected Probe's 312-byte watched record, instruction-entry arguments, position/order stores and the separate periodic countdown. Its existing ordinary-input prefix authenticates the first RAM view at step 4,201, selects the Probe, and issues the previously observed Move. A future controlled test should retain that prefix and one frame identifying the selected moving Probe; take a second RAM view during motion; issue a separately verified ordinary STOP gesture while the same actor remains selected; then take a third RAM view and a final frame after a bounded settling interval. Compare the watched order/target stores and the post-settling position stream with the moving interval and retained record identity. A cessation at a natural destination, a different selected actor, an unverified menu label or an absent writer is inconclusive. A frame alone cannot prove movement ceased, and the periodic countdown is not a game clock.

The applicable limit remains three 8 MiB cache-aware RAM views, at most three 614,400-byte frames, 63/64 MiB owned output, 8 MiB Metal-compatible per-file limit, 175/180-second execution deadlines, 5 GiB reserve and the shared native lock. The established fixed event buffers and their overflow failures also remain in force; additional continuation can exhaust them, so the previous run's margin is not a guarantee. The first-view hash, input prefix, observer binary and source must be pinned and verified, and the proposed exact steps, capture markers and event-budget admission tested and reviewed before a native attempt. No guest-memory injection, external state or CPU rebuild is needed in the proposed observation. It remains an authentic same-process hybrid restore, not a fresh-interpreter or hardware timing claim.

The next prerequisite is a primary N64 control source or a retained native interface view that actually identifies how this Probe can receive STOP. If the gesture requires a button unsupported by the existing observer, source-backed input support, tests and a separately pinned build are required first. No STOP, speed, independent game-clock or second-actor conclusion is claimed here; no new emulator run was made for this audit.
