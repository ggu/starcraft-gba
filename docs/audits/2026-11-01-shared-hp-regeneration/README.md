# Shared HP regeneration source audit

This is a source-only eligibility and persistence audit. It changes no gameplay and is not evidence of native N64 execution or regeneration timing.

An already-staged `units.dat` from the normalized USA ROM SHA-1 `a36d91b5aac7bb95df0d7de5f9814f5270e25c2b` has BOLT path `00C/001`, length 19,876, and SHA-256 `54356d7585c66cd463346996444fd208336eaacf6335d30eb2688aa73c9cb2df`. Its staging receipt SHA-256 is `45fa2f1f5f7163af84950ff999795cf9906055fcf749e31e6f6482e7c8ede7f8`. The pinned OpenBW `data_loading.h` SHA-256 `5bce24b2f441062f501cbb2fc837a5ac3637ab5dc00c783e276e08ad87a41629` describes 228 units and puts the little-endian 32-bit flags column at byte offset 7032. Its pinned `data_types.h` names bit `0x80` as regeneration. Reading that column without extracting or modifying the staged file yields exactly 50 IDs: 35, 37–57, 62, 103, 104, 130–153 and 201. They exactly equal the independently pinned BWAPI list from `UnitType.cpp` SHA-256 `7f16832dac82b8a739a07616ec0e61bc2c68a34b873f779cca8742de4832c76b`; neither set has an extra ID. The derived 228-byte zero/one vector SHA-256 is `29741f6688fb9ae03b6df2cc3eab0ccb5b308e7965307c521ea241e225691125`. Larva 35 is flagged; Egg 36, Cocoon 59 and Lurker Egg 97 are not. No proprietary table bytes are committed.

Pinned OpenBW `bwgame.h` SHA-256 `5ee316ca2c008c9252f7fde7444ca5dc7f35440549be2576dc37fa228fb31ae6` runs `update_unit_values` for visible and hidden unit lists. A completed actor with the regeneration flag and positive, nonmaximum HP gains 4 Q8 HP per source update. Thus its reference code does not blanket-exclude a completed hidden or loaded actor. Its Zerg-building morph path clears the completed status during morph and restores it on completion; its preserved HP value carries the fraction through the transition. This is OpenBW reference behavior using N64 data, not proof of N64 code's own order or hidden-unit behavior. The project's 24-source/30-engine mapping yields the existing Z5 adaptation of one integer HP per 80 active engine updates; full fractional damage and subframe ordering remain approximations.

A prospective common service should resolve an actor's authenticated raw type or validated standard-type fallback, consult the 50-row fact, and gate by the source-equivalent completion state rather than owner race or mission. It must run once per active engine update, freeze while paused, apply to every eligible owner and relevant mode including custom and Showcase, and handle the hidden/loaded case according to the supported reference model. Use no new BSS or hidden global clock: where a type is verified unshielded and its field is not reserved for another service, the existing serialized remainder can hold the bounded phase; preserve existing Z5 raw-37/raw-51 phase meaning. A full-HP actor's canonical phase and damage/regen update order must be specified and tested. Preserve the partial phase across incomplete in-place morphs and resume only upon source-equivalent completion; new unfinished construction and source larvae require their own correctly mapped completion semantics. Ordinary save/load, death, slot reuse, transfer, morph and full-HP transitions need direct tests.

This field is typed, not universally free: shielded actors and Battery recharge use shield phase; Terran buildings use it for packed burn damage and ownership; P6 wall traps and other special actors have independent meanings. Existing Z7 Egg validation requires zero, consistent with Egg's non-regenerating source flag, but the Creep Colony morph validator also requires zero and must be reconciled before a partially regenerated completed colony can enter or survive a morph save. Construction HP, morph HP scaling, compact/legacy/P7 typed save codecs, candidate preflight and old-save semantics must be audited together. Do not globally reinterpret preexisting fields or relax unrelated service validators. No implementation or new native qualification is claimed here.
