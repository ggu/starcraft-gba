# Where Z10 mixed battle orders spike without new route fields

This measures the [combined Z10 Carrier and route-lookup preview](../CARRIER-PROJECTILES.md#where-the-mixed-battle-spends-its-cycles), not the default release. Start from its ordinary frame 15,927 journal in the mixed three-AI Blood Bath battle. Advance 1,000 updates to frame 16,927, then save through START/B. Both ARM cartridges match all 43 watched world and arena cuts against the original continuation and write the same full 32 KiB SRAM. Route hit/build counts match the earlier exact control on every update. Reads came from the pinned observer at the established breakpoints; the observer did not write guest state. These are emulator cycle counts, with no physical GBA FPS claim.

The control is byte-identical to the prior combined Z10 ROM. The diagnostic is built from `87de7fc4ec8aa38711f2eb329124132a49acd324` (control base `aa42406`) with `SC64_DIAGNOSTIC_ORDERS` and `SC64_DIAGNOSTIC_ORDER_TAIL`. The larger optional setup breakdown failed the existing IWRAM link assertion, so it was excluded. The diagnostic's IWRAM ends at `0x03004fe8`, 24 bytes before the unmodified guard. The control uses 1,006,459,911 timed loop cycles, versus 1,034,609,844 for the diagnostic (+2.80% including code placement and instrumentation). The corresponding elapsed emulated clocks are 1,006,866,202 and 1,035,003,283. Treat the diagnostic numbers as attribution and the control numbers as the cycle baseline.

## Two separate order spikes

The 564 updates with zero new route fields still average 329,776 stock orders cycles (p95 483,110, using the nearest-rank convention). The 37 updates with zero field builds and zero hits average 301,976 stock orders cycles. In the diagnostic's zero-build set, the actor pass averages 329,596 cycles (p95 407,694), and the postlude averages 27,908 (p95 194,152, maximum 995,227). The movement repath scope is far smaller in the common case (mean 7,612, p95 23,319), with a separate 466,442-cycle outlier.

At frame 16,902 the existing orders timer still reads 1,267,192 cycles with the [optional fast target link](2026-11-12-target-index-bulk.md#reuse-validated-cells-and-occupancy-bits); its 2.23% average orders improvement does not address this spike. Frames 16,902, 16,658 and 16,626 spend most measured orders cycles after the actor pass. Frame 16,194 instead spends 466,442 cycles in two mover refreshes; this timer includes both `direct_path_clear` and fallback `path_next_tile`, so a zero build count cannot distinguish a slow ray check from cached or fallback route work. Frame 16,076 has 15 new fields and 1,074,281 worker cycles after subtracting measured movement within workers. These are inclusive measurements: repath is part of movement, which may itself run inside worker work. Do not add these scopes together.

## What can run in the postlude

Preprocessing the exact control vector shows only the Carrier projectile service and shared transport call in the interval from `update_orders` return to the orders clock read. The Nuke and Yamato paths are compiled out. Nydus is before the actor pass, and production and ordinary defenses are after the orders clock read. The transport function is called again later, outside this timer.

The projectile service skips `frame % 5 == 4`. All 279 postludes longer than 10,000 cycles occur in the four enabled phases; on all 200 skipped updates the longest postlude is 125 cycles. This strongly points to the projectile service in this workload. It does not give independent times for the two calls or prove that each sampled peak is projectile work alone.

- The [projectile pass](../../starcraft/sc64_p7_projectile_adapter.h) walks the active chain (bounded at 100 rows), reads and validates arena fields, steps and validates motion, retires expired rows, commits changes, then dispatches each pending damage pulse. `hit_target` can invoke unit-death cleanup or building destruction, which includes invalidating the path grid. A prior 43-cut run of this segment sampled a maximum of seven active projectiles; that does not bound occupancy or callback counts at unsampled peaks. Rewriting motion or the codec without measuring the callbacks could miss the cost.
- The [transport pass](../../starcraft/sc64_transport_adapter.h) returns early if no transport order is active. Otherwise it scans the actor slots for unload orders and loaded units, can test up to 25 landing points per attempted unload, and can call cargo-removal or bunker callbacks. Its presence in the same timed scope is why the Carrier cadence alone is insufficient for a per-function claim.

The next narrow check should time those two calls separately on this same tape, and separate projectile row/motion/retire cost from impact callbacks with per-update visited-row, impact and retire counts. Replace the broader diagnostic counters for that experiment to preserve IWRAM margin. If payload processing dominates, use a checked runtime row path that avoids repeated work and verify exact arena and SRAM bytes, including full-pool allocation, retire, slot reuse and malformed load cases. If callbacks dominate, profile the first expensive callback before changing ordering, cadence, or validation. Independently split direct ray checks from fallback routing around frame 16,194. No behavior change is justified from the current timer split alone.

## Why a zero-build update rebuilt route fields

The narrower route probe split the ground repath into the direct ray,
path-grid rebuild, cached-slot lookup, optional monotone witness, exact
field fill and blocked-origin handling. The same 1,000-update control
matched all 43 gameplay cuts, 58 indexed-page and palette cuts, and every
byte of the ordinary final save. The diagnostic also matched the
stock route hit/build counters on each update.

At frame 16,194, the direct ray took about 1,800 cycles. Two exact
nearby-root field fills took 455,606 cycles, despite the build count
staying at zero. One more nearby-root fill cost 227,745 cycles at
16,907. These are materializations of an existing lazy slot rather than
new logical route entries. Neither the direct ray, the monotone witness,
nor a path-grid rebuild explains these two steps.

Two changes address this path. The bounded cached gradient now carries
forward its row and column instead of dividing at every cell. The next
step can also read a lazy field when the existing gate proves the exact
preferred route to its root and that route runs through the requested
goal. If the gate rejects, the lookup still materializes the whole
field before examining it. The keep-fields oracle checks against fresh
tie-ordered floods and verifies that an obsolete gradient over a newly
closed tile materializes.

The gradient walk alone lowers whole-update mean from 1,006,922 to
997,655 cycles and leaves the 16,194 retry expensive. With exact lazy
reuse too, that frame's orders fall from 810,866 to 366,285 cycles;
16,907 falls from 518,498 to 294,140. The two route changes together
average 996,089 cycles per update on this tape. Both separate pairs match
all sampled world, rendered pixels and final SRAM. The physical GBA
and broader campaign timing remain open.

The combined candidate started from the same real custom SRAM and ran
the same 1,000 game updates. It matched 43 world/arena cuts, 62 indexed
pages and palettes, every per-update logical route build/hit delta, and
the complete final SRAM. The timing comparison uses the current control
with the [already fixed cold weapon scan](2026-11-17-render-first-update.md).

## Follow-up: retirement revalidates the whole pool

A second paired ARM run used the same byte-identical control, ordinary title-L load, 1,000 advancing updates and START/B save. The narrow probe (`379d8fe3c0e2505ef4fdbd5a581c37100748ce53`) replaces the broad order instrumentation with a projectile timer, nested impact callback timer and independent transport timer. It also reads visited rows, retired rows, hits and the slowest callback's target and pre-hit HP. It changes no emulator input or memory. Both legs matched all 43 watched state cuts, every update's prior route hit/build counts and the complete final 32 KiB SRAM. IWRAM ends at the same `0x03004d90` in both legs. Timed loop cycles were 1,006,459,911 for the control and 1,008,467,528 with the probe (+0.20%); elapsed clocks were 1,006,866,202 and 1,008,867,132. These changes are instrumentation overhead, not performance gains.

| ---: | ---: | ---: | ---: | ---: |
| 16,194 | 102 | 0 | 0 / 0 | 74 |
| 16,626 | 376,895 | 0 | 2 / 2 | 74 |
| 16,658 | 559,513 | 0 | 3 / 3 | 74 |
| 16,902 | 989,105 | 1,512 | 9 / 5 | 74 |

Transport never had an active order in this window; its highest measured cost was 99 cycles. The probe observed 1,048 visited rows, 157 retirements and 148 hit callbacks. The most expensive single hit was 912 cycles. At frame 16,902 the watched cut had 81 units and 50 buildings, with four projectiles remaining. The slower of the two hits took 756 cycles and came from projectile ordinal 10, source slot 4, against building reference 289 at 325 HP. It did not kill the target. That callback and transport cannot account for the nearly million-cycle postlude.

Without hits or nonretiring rows, 22 single-retirement updates average 185,653 projectile cycles, eight double-retirement updates average 375,258 and two triple-retirement updates average 559,602. Across the 883 updates without any retirement, the maximum outside-hit projectile time is 50,834 cycles. On this source vector every `sc64_compact_pool_retire` calls strict `sc64_pool_retire`, which walks both linked lists and checks all 100 row slots, including the canonical contents of unallocated storage. This accounts for the strong retirement-count pattern and identifies a bounded deterministic candidate without touching projectile cadence, damage or pathfinding.

The proposed live retire path uses the same unlink and insertion order for regular Protoss and compact previews. It preserves the fixed-format slot fields and canonicalizes the compact free row exactly as before. It verifies the touched links, endpoints, counts and current row in the exclusively owned arena, and falls back to the strict path if that check fails. Init, acquire, external packet preflight, decode, and save/export still do their original checks. The host differential exercises 5,050 retirements per format across all 100 capacities, compares whole arenas and packed records, verifies identical reuse order, and rejects malformed splice metadata transactionally. A paired ARM replay of the optimized ROM remains necessary to quantify savings and recheck the world, final SRAM and frame tails. The separate repath outlier remains outside this change.
