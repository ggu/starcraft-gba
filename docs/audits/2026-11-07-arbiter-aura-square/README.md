# Experimental Arbiter finder-square hoist

The opt-in `SC64_AURA_SQUARE_HOIST_PROBE` computes an Arbiter's clipped finder-square bounds once per eligible Arbiter rather than once per target. Both the indexed traversal and scalar fallback retain their existing target order, ownership, source identity, rectangle validation and exact distance tests. The flag is off in normal products.

The standalone independent scalar-vs-hoisted boundary/random geometry oracle and the actual P7 cache geometry/cadence policy fixture passed under ASan/UBSan with the flag both off and on. The two policy outputs were identical (SHA-256 `341182cf203068d618b6f0d3d81461e772aec96aa86d8c3f7a7e7720b6ecb4d5`); the standalone oracle output SHA-256 was `2b0cc13e5efb0adfb8e2756490f0bdd699dd0d756bb08c5f2dc908d49239b2a9`. A separate source review found no actionable difference in the scoped geometry and ordering.

Using frozen source `b09bdec1aadad9fca40e0228fad11bc925b0aaf6`, the ordinary P7-input P10 pair covered 958 advancing and 42 nonadvancing play calls, with three modal acknowledgments. All 1,000 timeline transitions and 11 sampled selected-world/full displayed indexed framebuffer/palette checks matched. Each sampled scene contained three raw-type-71 Arbiters. The control was byte-identical to the normal 32 MiB P10 ROM `317cc67d8f48b6771b3ebf4497c52b290466de49d097133b7b1bfdea65b34cd9`; the probe ROM SHA-256 was `ef2db198e09d124b372d19560f064ca4ed8778ab9e0837dfd553e50c25d2a78f`. Both guarded links left 19,992 bytes EWRAM and 2,056 bytes IWRAM.

Mean elapsed cycles fell from 2,306,990.83 to 2,296,994.49 (0.4333%); peak fell from 3,956,748 to 3,956,322. This is a small result from one scene, not a material route to 30 fps, a hardware measurement, every-frame pixel proof or full campaign qualification. The probe remains disabled. Pair receipt SHA-256 `a028b31eaa6a6d43e8e231149cba85030e89b55380827307949917d1572d86bf`; the 595-input manifest was `47f5ac9fd8d74ef29e22c2296109c4f2ef2ea46e493f26c6cb9598058018e6ee`. All inputs were unchanged. The first replay launch failed before guest startup because an isolated copied observer lacked execute permission; its failure is retained, and the corrected mode did not alter the observer's pinned hash. Both successful replays used the already-validated links.
