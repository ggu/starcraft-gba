# Experimental Reaver parent death and STOP

The OFF-by-default human-control probe calls the existing graph-checked parent-lost adapter in the normal unit damage/death path before invalidating the parent slot. Hidden training and stored children are retired without refund; an outside or self-destructing child is detached and retains its live position, target and flight state. Before retiring hidden children the wrapper invalidates pending impact, Yamato, interceptor projectile and direct-attack references where those services are compiled, and invalidates the active spatial and target indexes. It does not claim to handle arbitrary malformed graphs or every possible external actor reference. STOP signals the existing outside-child self-destruct behavior and preserves the parent's packed paid queue and progress instead of applying the generic carry reset.

The inside/outside and STOP semantics follow the previously documented pinned OpenBW PC order and adapter audits; they are not a native N64 execution claim. The synthetic host fixture exercises the real paid queue, `game_update` training and launch, parent damage, STOP, no-refund behavior and parent slot reuse on both maps. A checksummed save, ordinary factory admission, upgrade handling and complete world atomicity are not established by this fixture.

`race_transport_destroy_cargo` has a separate guarded hook before it clears a transported parent. The current source cargo table does not admit raw83, so the test first checks that rejection and then explicitly injects an unsupported transported row and invokes the real cargo destruction routine after simulated carrier removal. This is a robustness test, not evidence that a Reaver can board a transport in gameplay. Cargo source data, other non-damage removal paths, all source references and full flight/save behavior remain open.

Four production-vector host builds passed with ASan/UBSan, with 40 successful runs: the five training/inside/outside/STOP/injected-transport scenarios on each map in each profile. The transported-row result is only the injected robustness test described above. The earlier fixture mistakenly introduced a nearby enemy before the stored-child checkpoint and accidentally allowed auto-launch; it was corrected and that failed run is not counted. A second transport fixture assumed the synthetic carrier was valid in every profile; it was corrected to invoke the cargo-destruction routine directly and that failed run is also not counted. No ARM memory/performance, hardware or full default qualification was run for this child checkpoint.
