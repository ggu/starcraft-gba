# P1 current-controller Flash HOST experiment

At runtime `30e5e7829b2147ce7ad7894c46a7f5355ef0beaa`, the explicit default-off HOST P1 stage wraps the existing campaign research-job payload (0x47) in a new Flash-only 0x49 record. A bounded versioned tail carries per-slot current controllers and existing Q8 HP debts; raw actor origin remains in the original rows. Candidate validation is detached, checks the P1 mission and unique human role, validates live controller-to-owner mappings, uses unknown for ambiguous predecessor identities, and publishes sidecars only after selection and final record revalidation. This is checksum and context validation, not cryptographic authentication. The first 32 KiB remains read-only; unsupported committed legacy or new-layout tags cannot authorize an overwrite.

The authored actual-game HOST fixture uses the real P1 rescue path: the Nexus retains origin slot 1 while its current controller is slot 7. A paid Forge job and half-point HP debt survive actual Flash save into a fresh-process load; the rescued Nexus still has origin 1/controller 7 and the job completes. Separate checksum-valid synthetic negative records check malformed 0x49 fallback, no valid candidate atomic refusal, an unknown new-layout tag and foreign committed legacy tags with bad length or checksum. Tests compare device bytes and live actor/building/controller/debt/research state on rejection. A failed live-controller writer preflight leaves the device unchanged and a subsequent valid save succeeds. The writer saves and restores the bounded suffix and each building padding byte on all P1 preflight exits, and checks the original full-prefix FNV checksum before writing.

Genuine separately produced 0x43 and 0x44 P1 predecessor records (no paid job) and a retained genuine 0x47 P1 paid-job record were loaded without retagging, migrated into the new region while preserving all legacy bytes, and loaded again in fresh consumers. The old 0x43/0x44 producer binaries are the retained binaries from campaign journal qualification `2e4ce4e50bf65e699cd55039a8b3c9a87aa89fbb`; their generated inputs hash to `8824ee4070cd1d89231360ff3653f55fc5c82b63cfabf1f197bfd2130ba2ad39` and `49d47e5ce030b82f3fcf59ebad970087e99df847fb607081513dcad362446509`. The retained genuine 0x47 file hashes to `1e90e2fb91c9167f389aa7a88cfbae70cfd57784bb081e4d61f3608ed1f1e002`. These are authored HOST worlds, not ordinary-input guest saves.

P1 producer/reader, fallback, legacy ownership and source-boundary checks passed under the shared native lock with strict ASan/UBSan settings and 593 prepared inputs unchanged. The earlier row-level P10 typed and Z10 compact composition tests separately passed worker cargo preparation and the detached Scarab parent/child graph validator after row-local normalization, including a forged child-origin rejection; this does not admit a combined Scarab journal. P10+Scarab facts were generated separately from the existing source generator and verified inputs, without changing the pinned normal bank. An initial missing Flash transport link and earlier fact-table guard failure are retained in private logs.

The new format is P1 HOST-only. The actual writer's re-selection under a concurrently stale descriptor has not yet been exercised by a P1-specific end-to-end test. Z9/Z10 paid Scarab, other campaign contexts, outside-child/impact persistence, full legacy combinations, ARM memory/stack, normal release, cartridge behavior and hardware timing remain unqualified. In particular, the existing worker-cargo/Scarab namespace and research/Scarab guards remain in force; successful row composition alone does not justify removing them. Normal ROM flags are unchanged.
