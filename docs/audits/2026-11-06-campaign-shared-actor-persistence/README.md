# Campaign shared-actor persistence: admission audit

Read-only source audit of `bd4dec9bdad88eb6d9ae70b90e3ea4f8908fd75c`, the engine base of the rare-dispatch candidate `74d0bad0200e64ef290f1b0c71a04ae9c63c425b`. No persistence implementation is enabled by this audit. The objective is the same shared engine and faithful persistence in all 30 campaigns and custom games; the current candidate does not meet it. Canonical source documentation currently describes 29/30 exposed campaigns, with Z10 outside the canonical Zerg profile. A mission appearing in the matrix below is an obligation, not a claim that its current product, controller or ROM is qualified.

## Established boundaries

* Under `SC64_SHARED_ACTOR_FULL_HOST_STAGE`, `race_save_game` rejects `!race_mode` before creating a campaign record (`starcraft/race_save_adapter.h:1654`). Removing this line alone is unsafe.
* The FULL writer selects one outer/inner pair with Egg, Guardian and Scarab feature capabilities (and extended events in the flight pair); those bits describe the selected schema, not which actors happen to be present. The loader authenticates the selected pair and subsequently invokes `race_combined_egg_candidate_valid` for an Egg-capable candidate (`race_save_adapter.h:3226` and `:3231`). Its entry and owner checks require custom `state[0]==1`, 1–3 bots, custom player identities and `raw_owner==-1` (`:560–625`). Thus merely allowing a campaign writer creates records that the combined reader rejects even when the actor set is empty. Do not repair this with an empty-campaign exemption.
* The older independent `SC64_SHARED_EGG_JOURNAL_HOST_STAGE` path has a different owner callback for Z8 and Z9/Z10, and Z7 has its own legacy Egg path. They are evidence of separate policies, not a complete all-campaign validator. The combined `SC64_SHARED_EGG_CUSTOM_SERVICE` selects its own producer flags; in this composition `race_shared_egg_context()` is custom-only in addition to legacy Z7 (`race_adapter.h:154`), not an all-mission Egg service. The old Egg candidate code explicitly notes that mission PUNI admission is not yet enforced by that producer. Safe persistence cannot claim a game-wide service that the live producer does not supply.
* `race_guardian_source_map_valid` rejects any source raw-59 row and raw-133/137 rows carrying the paid-morph bit; P6 nonsprite doodads are also inspected (`sc64_guardian_candidate_validation.h:11–30`). The wire codec converts staged Cocoon to an Overlord-typed raw-59 row and interprets raw 59 as staged only with the selected Guardian capability (`sc64_guardian_wire.h`). The broad source-row fence avoids an unresolved ambiguity: a source-placed passive Cocoon and a paid Guardian morph can otherwise share raw identity and serialized fields. A feature bit, a timer that looks plausible, or a scan of current source rows does not prove the actor's creation history. The paid building marker has the analogous source-bit collision. Check all source rows, scripted creations and codec domains, not just one mission's initial map.
* The Guardian candidate origin validator permits a saved active current controller to differ from original source owner while checking immutable source race and source PUNI. In contrast the current Zerg campaign producer requires the source-to-live owner match, and Z8/Z9 world rebinds also enforce that mapping. T4/T5 and late Terran adapters have distinct rescue/current-source rules; late Terran can refuse to infer an ambiguous force member (`sc64_t4_world.h`, `sc64_t5_scenario_adapter.h`, `sc64_terran_late_world.h`). These are different contracts. A blanket equality breaks legitimate transfers; accepting any active owner permits impossible ones. Producer, transition, save and post-load rebind must agree for each mission.
* A real Z7 legacy-journal load has been observed failing with frontend error 89 in the candidate. That is a generic rejected-selection outcome, not proof of which internal predicate failed. The feature-zero/tag-pair path, inner-version preservation, Z7-specific validator and legacy row interpretation require instrumented, detached validation before assigning a cause. Passing custom feature-zero fixtures does not qualify that campaign migration.

This matrix is an inventory of source entry points, not a claim that each table authenticates every actor or that every named mode can currently produce every job. The live Guardian start path explicitly selects some non-Zerg contexts (P8, T5, T6 and late Terran) but the candidate origin function only dispatches the listed Zerg mission families, so non-Zerg/captured producers can be admitted by one side and rejected by the other. Guardian campaign construction and early permission switches are independent HOST experiments and are not enabled merely by the current ARM qualification flags.

## Smallest faithful general design to investigate

1. Build a bounded immutable mission-context descriptor keyed by the authenticated saved mission and product/codec: map dimensions, source slot identities/races, source program revision, PUNI provenance and current-controller/transition policy. Cover all 30 named missions, including absent Z10 vector; fail closed if a required table or transition is unverified. Custom gets a separate context derived from the selected, validated custom configuration. Avoid live globals while decoding candidates. Derive producers' and candidate validators' permissions from a shared contract, but preserve each mission's distinct policy rather than normalizing away source/current ownership.
2. Define explicit authenticated per-row origin/job identity for paid Egg, Guardian morph, paid Hive/Greater Spire, Scarab child/parent, and source/native passive actors. Preserve original source slot, effective current controller and any reachable rescue/capture transition separately. Work out a bounded codec/journal representation for each compact/derived/typed row and prove it fits unchanged RAM, SRAM and stack guards. If current bits cannot encode source-created versus paid state unambiguously, introduce a new versioned representation or sidecar; do not guess from raw ID, HP, timer, a marker bit, producer survival or an outer tag. A checksum/tag binds a record format and protects integrity, but does not prove a historical payment. Record only provenance the engine can establish at creation, and enforce consistency throughout transitions.
3. Reconcile source permissions at job admission, producer-to-child attribution and post-capture control: immutable original provenance and permission relevant at the actual order must not be conflated. A previously paid job can outlive the producer and prerequisite, so load must not require them still alive; conversely it must reject a newly forged actor/owner/permission combination. Retain visible partial HP, progress, selection, orders, damage and refund-once behavior. Explicitly cover source native Cocoon as its own identity and source 133/137 flags, including P6 doodads and scripted spawns.
4. Use a single bounded commitment model shared by live admission, triggers and detached save validation: live occupied slots; paired Egg extra births; every queued building product and multiplicity; Carrier current child and paid queue; Scarab actor lifecycle/impact packet; mission-specific pending source creates and future obligations. Account exactly once for occupied vs pending and for all owners. Existing Z6 AI pending-create accounting and P7 Carrier reserved creates are mission-specific (`sc64_z6_runtime_adapter.h`, `sc64_p7_carrier_training.h`); `race_combined_egg_candidate_valid` currently counts Eggs, ordinary queues and Carrier carry but cannot establish all trigger reservations. Do not solve this by reducing capacities or accepting saves that later deadlock a mandatory spawn.
5. Preserve atomic two-slot selection and version-scoped migrations: validate checksum and exact outer/inner/tag relation before row interpretation, try candidate records through the existing prepared-selector policy, decode into detached bounded storage, apply migration exactly once, validate all mission/actor/queue/impact/cargo/transport/projectile invariants, then install world state. Preserve an older valid slot when a newer record is malformed or unsupported; verify ordering and actual selector behavior rather than promising fallback that is not implemented. Keep feature-zero legacy actors in their original representation, including raw-36 Overlord vs Egg, and reject feature retags that would reinterpret them. Instrument the real error-89 failure before changing the reader. Test old/new mixtures and torn writes, and preserve existing generation compatibility or explicitly define a safe migration policy per product.

## Required failing and regression fixtures before any admission change

* From real independent predecessor writers, save/load every T1–T10, Z1–Z10 and P1–P10 under each product that exposes it; use normal frontend save, fresh process load and continued play. Include saves with no staged actors so a mode gate does not mask general legacy regressions. The observed Z7 error-89 record must become a reproducing boundary test and identify the actual rejecting predicate.
* Across custom, Zerg campaign and non-Zerg campaign contexts: paid Egg (single and paired products), dying/dead rows, completion with one slot left, cancellation/refund-once, producer destruction, owner changes and subsequent prerequisites lost; reject invalid target, malformed timing, wrong source/controller/PUNI and insufficient truly available capacity. Check raw-36 Overlord across feature-zero, Egg-capable and mixed older/newer records without retag reinterpretation.
* Source-placed raw-59 Cocoon, paid morph, source-created Cocoon after initial load, identical-looking rows, killed/reused slots, paid cancellation and completion; coexist with imported raw-133/137 bit patterns and P6 non-sprite doodads. Require a positive identity proof in the new format and reject ambiguous or forged rows atomically; do not reject a legitimate passive source actor simply because another actor is paid.
* Every rescue, capture, given-unit/building and trigger-owner transition supported by each mission: original slot, current controller, race and PUNI before/after transfer; distinguish valid late-Terran force ambiguity from a forged owner and test captured Zerg producers in P8/T5/T6/late Terran plus unsupported early contexts. Include hostile owner/race/source and source table/revision mismatches.
* Simultaneous commitments at exact capacity: paired Eggs, all owners' building queues, Carrier current child plus carry queue, Scarab child and impact, and each mission's pending source-create triggers. At the boundary compare uninterrupted and save/reload traces, spawn order, waits, resources, HP and RNG; test overflow, destroyed producers, reused rows and invalid queues. Do not omit future mandatory trigger obligations.
* Per-codec selected-record matrix: valid legacy/newest, valid staged/newest, both orders, corrupt/torn/truncated/incompatible newest with valid predecessor, feature0/feature1/combined/flight pairs, wrong inner/outer tags and malformed extensions. Assert selection result and byte-for-byte unchanged live world and SRAM on rejection; run fresh-process SRAM and repeated save/load/cancel tests.
* Run semantic HOST tests and actual guarded ARM links for every affected product, with `.su` call-chain review, runtime stack high-water, normal-input campaign completions, ownership-sensitive replays and bounded 1–3 AI performance. The current placement candidate's synthetic diamond timings and one Z7 prefix do not establish all-30 gameplay, art or near-30-fps performance.
