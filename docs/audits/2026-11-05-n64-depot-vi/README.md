# N64 Supply Depot: observed VI-field interval

A private, ordinary-input N64 reference run on 2026-11-05 observed a Terran Supply Depot from its first visible build-progress bar to its completed supply increase. The selected custom-game settings were Melee, Challenger, one human Terran against one computer Zerg, with the in-game Game Speed slider visibly set to MAX. Four starting workers and 4/10 supply were visible. This is one setup and speed, not a rule for every N64 mode or speed.

The host-controlled input pressed A to confirm a green placement at captured VI field 17251 and released it at 17259. The selected SCV then traveled to the site. The mineral display showed 370 at field 17574 and began decrementing at 17575; it is an animated display and does not establish the precise internal debit time. At field 17578 the worker was at the site and the build-progress bar was not visible; at 17579 the bar was visible. Field 19088 showed 4/10 supply; field 19089 showed the Depot and 4/18 supply. The supply display does not establish the precise internal completion update. The interval between those two visible boundaries is **1,510 emulated VI fields**. Those boundaries describe rendered observations, not necessarily the exact internal start and finish updates.

The whole capture **failed**: its bounded host queue reported `ring_overrun` after field 19767, and the terminal record correctly indicates failure. An independent stream pass found all 2,520 image records in the contiguous prefix 17248–19767, including every field in the reported interval; the footer's final field was 19785, so later images are missing. The prefix evidence is narrower than a successful complete capture. The capture began before the placement input; no guest memory or ROM writes, save forging, unlock modification, were used. Raw frames, ROM, saves and input files remain private.

The private reference executable was a separately built ares v148 N64-only tree at official source commit `0aafd85789215e84e1e43415c07d4c88461b7899`, with host-only scanout and controller logging; executable SHA-256 `97ae1b615362ebced4abb31bea727def2624bc038e8fabc8f8ae4c571d479413`. The owned normalized USA ROM SHA-256 was `e7d21880c13953b45b8f8db6b2b6cfa02daa29d35b23799a967e96f21001b020`. The private stream SHA-256 was `64679e7ecc019ec316654f0275ed6af38cbed1462d13ff14913a1fb8d64442ff`. The private input shim SHA-256 was `ba9227ef9a14deec020b62affc7d92eb015d51d44d90eb8edacf1cb784f7ff70`. Field numbers came from active VI field rollover, associated with the Vulkan scanout generation; controller records are the emulated port's first state and subsequent state transitions. A prior independent bounded calibration produced 313 consecutive field images and a success footer, and a paused screenshot exercise did not grow that capture. The scanout may persist or blend a previous image, and the field counter is neither a VI-interrupt count nor a game-update count.

For comparison, this repository's `starcraft/race_rules.h` describes the Depot with 600 source build frames and cost 100; the existing 5/4 conversion in `starcraft/race_adapter.h` corresponds to 750 GBA update ticks. This observation does not establish a conversion between N64 VI fields and game updates or demonstrate a timing discrepancy at equivalent game speed. Do not change construction timing from this single measurement. The repeat below addresses capture I/O backpressure and records a successful terminal.

## Clean repeat with bounded host backpressure

A second fresh-flash Melee/Challenger run used the same human Terran versus one Zerg AI configuration and again visibly selected MAX speed. It independently reproduced the display-counter interval with a complete capture: the mineral HUD was 362 at field 11280 and began decreasing at 11281; the HUD showed 4/10 at field 12794 and first showed 4/18 at 12795; the displayed supply increase does not establish the exact internal completion update. The two observed display boundaries were **1,514 VI fields** apart, the same decrement-onset-to-completion difference as the first run. This is not a claim that the animated mineral counter marks the exact internal construction-start update. Unlike the first run, this repeat did not show a selected build-progress bar at onset.

The closed repeat stream contains all 3,408 consecutive field images 11043–14450 and a success terminal; the placement A state was observed on controller port 1 at field 11046 and released at 11054. All four virtual ports were observed, with unchanged controller polls compressed to state transitions and per-port poll totals retained. The capture queue reached 10 of 16 slots, with zero producer waits; its writer reported 3.186 seconds of aggregate host I/O across the complete capture. Those host measurements are diagnostic only. The private executable SHA-256 was `46e6c02a0c4327ac0c234ebcf3506bf520484bffbd9a14a3013b62735a59c47b`, and the raw stream SHA-256 was `42e8bc2d87f99e335125a4ceac87174f897c3b7ab3f2a03eeb5f22305b77f074`. This instrumented build used a bounded 4 GiB output limit and a two-second producer timeout on a full host queue; either timeout or incomplete output invalidates a whole-capture claim. No such failure was recorded in the repeat. The field-to-game-update and equivalent-speed limitations above still apply.

An independent review verified the repeat stream's full field continuity, success footer, port totals, queue statistics and SHA-256. It also checked four boundary PNGs from the earlier failed capture against the corresponding raw field pixels. Those checks do not turn the earlier failed stream into a complete capture or establish a VI-to-game-update conversion.
