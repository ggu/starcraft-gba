# HOST late-Zerg Scarab capacity reservation

The experimental late-Zerg AI normally preserves 24 unit slots for human and scripted creation. Its paid Scarab allocator previously took any free slot and could consume this reserve. This default-off HOST stage checks the existing product-slot ledger before payment and again before allocating a child, requiring room for the 24 reserved slots, the new child and already committed ordinary/paired products. If pressure occurs after payment, the queued job waits; cancellation remains available, and the same paid job can resume when capacity returns. This does not change actor caps or make promises about unrelated spawn paths.

At `05b2eef28a6b71d0cd2a1f832ba4e25e3f4a3181`, an authored actual-engine Z10 fixture passed under strict ASan/UBSan: 24 versus 25 free slots, an existing paired-product obligation, no debit under pressure, paid wait and cancellation, paid wait and later allocation, and actual scripted Drone and Crystal creation from the retained reserve. Source boundary passed. At `a4159def80ef253256736de63877f332b9403847`, the existing Z10 paid-impact, custom Scarab and P1 controller fixtures also passed; their source and runtime were unchanged by the subsequent test-only addition. Both runs held the shared native lock and verified 593 prepared inputs. The initial `922001d6` run failed because the reserve condition was accidentally placed in cancellation rather than enqueue; the correction and failure are retained.

Run the optional prepared-input target with `make -f Makefile -f tests/sc64-zl-scarab-controller/Makefile SC64_AUDIO_DIR=<prepared-audio-dir> ZL_SCARAB_COVER_DIR=<prepared-cover-dir> test-zl-scarab-reservation`. The HOST vector retains Nydus and its existing guard, and fences save/load. Normal ROM flags remain off. This is not a full campaign, persistence, ARM, native cadence or hardware qualification.
