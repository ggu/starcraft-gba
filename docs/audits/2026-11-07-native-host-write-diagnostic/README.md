# Bounded host-write diagnostic design (not implemented)

The earlier packed-inventory run recorded SIGXFSZ on a host dispatch/system thread. It did not identify the write, file descriptor or path, and supplied no guest-order evidence. No emulator run or host interposition is performed by this design.

A candidate future observer could intercept host `write`, `pwrite`, and `ftruncate` calls in the owned process only, using a Darwin dyld interpose mechanism after its bootstrap and original-function binding are proven. A dedicated freshly created private regular file would reserve at most 32 fixed records, each containing operation, monotonically assigned sequence, thread identifier, descriptor, requested count or truncation length, observed current offset or append-mode file size where obtainable, `F_GETPATH` result or explicit error/truncation, and pre-call errno. It would contain no caller buffer bytes. Each record must be written before forwarding a potentially over-limit operation, because SIGXFSZ can terminate the process before the call returns; a best-effort post-call record may contain the actual return value and errno if it returns. An overflow indicator must distinguish a complete event stream from an exhausted ring. Recording would be limited to regular-file calls that may cross the existing 2 MiB soft limit, plus cases whose position or file status cannot be determined. A positive-offset, full-size or append case is a *snapshot*, not proof of the actual write position if another thread changes file state.

The forward path must invoke the exact original function once with unchanged arguments, preserve its return value and errno, not change fd flags or offsets, and never change the 2 MiB soft / 8 MiB hard RLIMIT_FSIZE. Save/restore errno around all metadata probes. Exclude both its own preopened diagnostic descriptor and the existing signal record descriptor; use the pre-resolved original positional write, fixed disjoint offsets and a strict <64 KiB file cap so logging cannot recursively intercept itself or exceed the soft limit. The inherited 175-second observer and 180-second wrapper deadlines, 5 GiB reserve, global lock, ROM checks, and 64 MiB owned-output allowance must not grow. Subtract the full recorder allocation from the existing 1 MiB miscellaneous-metadata allowance, not add a new allowance. A storage failure must set a visible incomplete status if possible and otherwise emit a bounded best-effort stderr warning; it must not silently assert a complete trace.

Several points prevent treating this as an approved implementation yet:

* A dyld interposed function may be called during loader or constructor activity before `dlsym(RTLD_NEXT, ...)` has initialized the original pointer. A bootstrapping design must not recurse, deadlock, or fabricate an I/O failure, including when loading libraries on other threads. Merely pre-resolving in a constructor does not prove this property.
* A hook may run in a signal handler or other context where `fcntl(F_GETPATH)`, `fstat`, `lseek`, locking, dynamic lookup, and logging are unsafe or change timing. The existing SIGXFSZ handler must be excluded without relying on thread-unsafe recursion flags. One must prove the exact hook/loader behavior before instrumentation is allowed to forward unknown calls.
* `F_GETPATH` identifies the descriptor at the time of the query. Close/reuse, concurrent seeks, and renames can make the path or offset stale. Append-mode writes require `F_GETFL` and a file-size observation; even then report the values as observations, not a guaranteed kernel write position. Path lookup failure and deleted/unlinked files need explicit statuses.
* A `write`/`pwrite`/`ftruncate` symbol hook cannot observe direct syscalls, `writev`, stdio paths that bypass it, memory-mapped changes, kernel or driver writes, or work in other processes. Darwin restricted process/library policies and libraries loaded after setup can limit rebinding. A matched call is evidence of an attempted operation, not proof that it caused the separately delivered signal; no record is not proof of no write.

Before any N64 use, an asset-free synthetic executable must cover normal/short/error writes, explicit and implicit offsets, `O_APPEND`, zero-size and exact-boundary cases, `ftruncate`, closed and renamed/unlinked descriptors, multiple threads, errno preservation, log recursion exclusion, ring saturation, and a real over-limit call at the existing RLIMIT. It must compare return values, errno and files against an uninstrumented control, retain complete logs and binary/source hashes, and demonstrate bootstrap before and during the same weak MoltenVK/Cocoa loading pattern. Native tests must hold the same global lock and ≥5 GiB reserve. Failure to observe a call through an intentionally direct-syscall or `mmap` control should be documented as a coverage limit, not treated as success. A separately qualified binary, bounded private receipt, and explicit review are required before a future single native diagnostic; this document authorizes no such run.
