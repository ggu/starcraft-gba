# Z3 shared Egg HOST stage

Checkpoint `d24d9cd3` stages Z3 only under an explicit HOST flag. Mission 14
uses the descriptor-authenticated current owner and raw producer source; paid
Egg admission and new-tag detached Egg rows both check that source's verified
PUNI product permission. Unsupported controller transfers fail closed. No
normal ROM flag is enabled.

The prepared owned-ROM permission header matches SHA-256
`c9ff17c083b5f9cb699aad753da5b496931dd818f5b50d315954926632457a03`.
With 593 input hashes verified before and after, the constructed actual-bank
fixture passed paid Zergling production, valid-shape denied Queen rejection,
atomic malformed-load rejection, a fresh-process journal and paired birth. A
separately compiled unmodified `aa8f43c5` engine wrote an initial-world Z3
old-tag save without retagging; its SHA-256 was
`978f911dd1cb5b46d4c9f9f392bfee8429e9bfe1a9ed3a4f30de6e0d7630f550`.
The candidate restored it and fell back to it after a checksum-valid newer Egg
with a denied product. This legacy test ran at `c6fc9833`; runtime source is
unchanged at `d24d9cd3`.

The Z3-specific boundary test used the actual paid Terran Barracks queue: one
free body reserved for a paired Egg blocked a Marine purchase without debit;
changing the Egg to a one-body target let the same purchase through. Existing
Z1, actual-bank Z2, Z8, Z9 and shared capacity fixtures passed at `d24d9cd3`.
The helper's Z3 wave-threshold heuristic itself counts each live Egg once;
queue admission separately checks global paired-body commitments. The authored
Z3 adapter orders existing units and queues paid reinforcements; no Z3-specific
post-init direct spawn call was found there. This does not establish all
original CHK or N64 trigger behavior. All native jobs held the shared lock and
checked a 4 GiB reserve; results and generated saves are private ignored files.
The fixtures set resources and prerequisites and do not prove ordinary-input
victory, ARM memory/stack, other missions, transfers, or common activation.

Z4 cannot be enabled by the same mapping alone: its explicit source mapping
and direct CreateUnit path need a separate authenticated reservation and retry
contract. The current callback checks only a free slot, and the scheduler
advances its cursor before dispatch and treats failure as a fault. In pinned
OpenBW 4b046d5f65302b10cb0a745f0fecd37ec85b20a8, trigger CreateUnit consumes
the action even if allocation fails; paired Egg birth still completes one child
if its second allocation fails. A policy that defers both is therefore a GBA
adaptation, not proof of N64 behavior.
