# Z7 worker-continuation comparison

A paired host experiment on source `e3919ec0` kept the current Z7 controller and every source file constant except `starcraft/game.c`: the comparison replaced that file with `b360f68b`'s version, removing exactly the 49-line worker-continuation change. Both used the actual Z9 vector, receipt-verified sprite/advisor/program inputs, the historical carried early-gas/home-army-R policy, a 200,000 host-tick limit, ordinary input, and ASan/UBSan. All 199 frozen/profile inputs matched before and after. Both builds succeeded and both runs reached the limit without a win: current at frame 199,432 with 53 enemy buildings, and pre-worker at frame 199,472 with 53. Reverting this worker change alone does not restore the historical win.

An observational-only host build logged the first 64 continuation decisions. Its complete input/checkpoint trace matched the uninstrumented current trace byte-for-byte. The first continuation was human raw-owner 3, unit slot 85, mineral 51 to 57 at frame 5,667; the next was another human worker at frame 5,698. The first adaptive input difference in the controlled pair was host tick 5,854, after the first continuation. That ordering does not establish which state change caused the input decision. The first observed hostile raw-owner 4 continuation was at frame 12,202. These are observations, not a quantified estimate of income.

The retained earlier carried-Z9 winning trace first differs in adaptive input at host tick 3,040, before the first observed continuation in the current run. The historical run is not an otherwise identical source/input comparison, so this identifies an earlier divergence boundary rather than its cause. Do not transfer its win or physical replay to current source.

Z7's adapter explicitly binds the human to raw owner 3 and the hostile side to raw owner 4 and its source-shape validation requires unique live owner bindings. Worker depot selection checks live owner equality. `add_owner_resources` passes the live owner to `race_add_owner_resources`, which credits SIDE's global wallet or `race_minerals[owner]` and `race_gas[owner]`; the authored Z7 AI selects raw-owner 4 producers and queues against ENEMY. Thus hostile retargeting can affect the ENEMY wallet, but this mission does not establish pooling of multiple hostile raw slots, nor does the available pair establish a loss caused by that income.

The source-only diagnostic and all exact argument vectors, paired logs/traces, instrumented logs and hash results remain in the isolated checkout's `.qualification/` directory. No guest state, objectives or limits were modified. Further attribution needs a controlled comparison against the precise retained winning source and input vector, with observation around the first host-tick 3,040 divergence; changing worker continuation alone is not a supported fix.

## Winning trace provenance and bounded text-box hypothesis

The retained winning trace SHA-256 `42e9a86021b3a16f6f67d2e19f3e475c4c98096799ce1abdc652f9117359696a` is the Z9 carried trace referenced by `2026-11-05-z9-carried-arm`: production source `0997e2fc`, with its canonical Z9 vector and the early-gas/home-army-R arguments recorded in the retained `carried-host/run-controllers.py`. The historical controller source at that commit hashes `83c4c7214837d71b58feb44894b74f92be4bd8210e282c6e0a3fcb4485432e27`; current e391 controller hashes `adcc34c182ff7825fbc521542736a8052e53436f2b6cf00dc97d54913483b15b`. Their controller diff consists of the five added building-deselection lines. The wider source differs in 74 files under `starcraft`, so the historical win is not a current-source baseline.

The historical retained build command and current command use the same Z9 feature vector except current adds `SC64_TEXT_BOXES` and its header path, plus `GBA_NO_DEBUG_INPUTS` which does not affect the host translation unit. The exact Z9 sprite bank `fafb2a0a...`, generated Z8/Z9 programs `ab3fad9e...`/`fab0840f...`, and advisor header/blob `73754a61...`/`bd0adfd0...` match the historical prepared receipt. A compiler dependency scan found three actually selected generated headers whose hashes differ from that receipt: weapon source `99efc112...` versus `0e03fcc5...`, unit facing `ade3d8f7...` versus `2da9aab3...`, and unit walk `0b117262...` versus `41cf024e...`. Other differing frozen-bank paths were not selected by this compilation. This establishes input non-equivalence, not their effect on gameplay.

A read-only diagnostic compared the current source/controller with text boxes enabled and disabled, holding the remaining inputs and early-gas policy fixed. Each requested a 3,200-host-tick prefix; both stopped at tick 3,355/frame 3,248 because the controller finishes its in-progress macro before checking its bound. All 405 recorded input events matched. The diagnostic recorded pressed inputs, text-box queue/host-acknowledgment counts, screen/mode, cursor and Z7 AI clock; no box appeared or was acknowledged in either prefix. Source host fixtures normally auto-acknowledge boxes at the end of an update unless `SC64_TEXT_BOX_HOST_MODAL` is set. Text-box enablement therefore does not explain the observed tick-3,040 input divergence in this bounded test; this is not evidence for disabling production text boxes.

At tick 3,040 the retained historical and unchanged current-source controllers both emit held/pressed `336`, while the modified controller emits SELECT (`4`), consistent with its added deselection path. The unchanged current-source controller first differs from the historical trace at tick 6,141. Both current-source controllers subsequently fail to win at the same full bound, so the added SELECT alone does not explain the missing win. All diagnostic logs, argument vectors and traces remain under `.qualification/`; no source or generated input was altered for the production build. A targeted next experiment should recover the three exact selected historical headers and compare a short prefix under the historical source/vector, independently confirming hashes and source provenance before testing any candidate correction.
