# N64 cadence follow-up: source-only observation plan

No emulator, native build, guest state change or new game-data capture was performed for this note. The [prior bounded interpreter observation](../2026-11-05-n64-order-cadence/README.md) found four same-process actor records consistent with raw-type-7, owner-1, 60-HP SCVs, and one timer decrement per actor in each of 126 complete candidate-countdown decrement intervals. The separate linked-list countdown's initialization and reload are not a verified active simulation clock. A different pause/speed-correlated word is RNG-like, and the old timer and VI counts must not be reinterpreted as a proven update clock. The prior observer's physical addresses and private trace capsule are not present in the public audit. A scoped read-only filename search of the known N64 reference worktrees and protected checkout's `.local/n64-ref` did not locate that capsule; no address is asserted or reused across processes here.

The pinned ares v148 source revision is `0aafd85789215e84e1e43415c07d4c88461b7899`. The existing source-integrated ordinary-input bridge is `experiments/ares-headless/interactive.cpp` and `interactive.py`; it has bounded video/input callbacks but no actor-memory or CPU-store observer. Its input mapping now exposes C directions, while an actual STOP input must be verified against the original controller and mapped if absent. It accepts ordinary commands and makes no guest writes. The original emulator source remains immutable; any observer must be built separately and explicitly qualified.

Candidate source integration points, requiring implementation and review before any run:

* `ares/n64/cpu/cpu.cpp` `CPU::instruction()` branches between cached JIT execution and interpreter execution before `instructionPrologue`. `ares/n64/system/system.cpp` recognizes `Recompiler`; set it false and verify the actual interpreter path, since the option API alone does not prove acceptance. A narrowly filtered interpreter PC-hit counter can timestamp candidate dispatch-entry instructions once independently located; it must distinguish a real active world-update boundary from calls that continue during pause or merely process the linked-list stagger.
* `ares/n64/cpu/memory.cpp` `CPU::write<Size>(PhysAccess,data)` sees a successfully translated CPU store before cached or uncached write and has physical address, size, data and `cpu.ipu.pc`. A bounded host-only hook can retain events only when the entire store is contained in explicitly permitted RDRAM spans; record sequence, writer PC, width/address/value and current control phase, without guest reads inside the hook. Aligned and split stores need accounting. The hook does not cover independent DMA or all cache-writeback effects; `ares/n64/rdram/rdram.hpp` `writeBurst` writes outside the ordinary `Writable::write` path. Absence of CPU stores does not prove no other agent changed an actor.
* `ares/n64/cpu/dcache.cpp` `DataCache::readDebug` uses a matching cached line before falling back to a bus read. Direct RDRAM alone can miss dirty CPU cache data, while an unrestricted debugger/bus read can touch MMIO. A read-only sampler must first validate the entire requested physical range against actual allocated RDRAM, then use a cache-coherent, non-mutating cached-line hit and direct-RDRAM miss path; do not call a generic bus read on an unvalidated address. No debugger writes, savestate injection, MMIO reads or guest-memory edits are allowed.

Smallest useful experiment: in fresh custom play, identify two distinct same-process actors by repeatable read-only field candidates correlated with visible selection and ordinary movement, not a historical address or type/HP alone. Record actor type, owner, identity discriminator, position, order and candidate local timer at bounded control/observation points, and reject any interval with ambiguous selection, reuse, untracked ownership or conflicting identity writes. With one actor as control, issue select/Move/Stop to the other using real emulated controls; then reverse roles. Record independently established dispatcher-entry PC counts and timer writer PCs separately from VI/callback labels. Include pause/resume and a speed change as falsification tests, and repeat from a genuinely fresh process/reset with actors rediscovered rather than reusing addresses. Retain instruction/controller, snapshot, input and source provenance. Compare per-actor timer writes and observable movement/order transitions per independently witnessed dispatcher invocation; do not assume one invocation per VI or skip complete actor updates.

The prior audit reports a task-wide snapshot ledger with 64 MiB of 256 MiB remaining. Before execution, recheck the actual ledger and approve a bounded allocation; for example, four 8 MiB bookends across two fresh processes consume 32 MiB, leaving room for failures while preserving the limit. Snapshots are not atomic with asynchronous graphics. Bound the CPU event ring, output, wall time, trace intervals and number of trials; run under the shared native lock and disk reserve. A safe implementation needs tests for address range/overflow, cache-hit versus direct-RDRAM reads, event-cap termination, writer-PC identity, controller mapping and fail-closed interpreter configuration before any native capture. More orders, reset/death/transport, JIT comparison and speed coverage remain necessary before proposing an engine optimization.
