# Contact geometry table: carried Protoss and Showcase

The existing CONTACT blocked-steering table replaces arithmetic with a ROM lookup for carried Protoss P7–P10 profiles (including the P1–P10 campaign and their skirmish) and Showcase when its contact cache is enabled. Z7/Z9/Z10 already selected this table. Historical P4–P6 profiles and the non-Z/P-facts Terran profile are unchanged. The table contains authored integer math, takes 887,250 ROM bytes, adds no persistent game state, and falls back to the original calculation outside its domain. It changes neither collision policy nor movement cadence. The generated header and tracked configuration fragment are explicit build prerequisites.

Using production-equivalent f9dc1179 runtime, a captured normal P10 compiler vector and the ordinary P7 input tape, separate baseline/table replacement-loop ROMs measured 958 advancing updates at input calls 8020–9019. Mean full-loop guest cycles were 2,245,337.97 → 2,201,952.51 (1.93% fewer); peaks were 3,955,676 → 3,916,430 at call 8347. All 90 sampled actor/fog/frame/pixel checkpoints matched. Baseline/table timing ROM SHA-256 values were `c980b06f2f349dc09046d0f165d1148f7921996f8fa326c8fbd05e6249aa7a98` / `9652f199bac49b614eb20693908676ef3d7ddc630cbe189042472155ba4b3d93`. This is one emulator window using a replacement main, not a full mission, hardware, or near-30-fps qualification. All 1,958 prepared inputs matched the pinned manifest before and after.

The generated table oracle passed 887,250 independently calculated entries and exhaustive arithmetic/fallback-domain checks. With actual normal P10 flags, independently built baseline/table ASan/UBSan fixtures emitted 33,761,288 identical bytes of per-query masks and inputs (SHA-256 `e3e47e8415e38748263b8e458540791b5b3edbc3a1bbfb5f318bef6bb26cc182`), covering randomized slot reuse, morphs, loaded units, bucket moves, active/inactive index fallback and eight scalar step-query comparisons per mask. On the actual Showcase vector the equivalent streams matched for 33,727,496 bytes (SHA-256 `786770b4476aedc904594ef7830c961497a271172c12ff924f494dc87cc0c6bf`). A separate focused eight-scene actor/building/fog/full-frame pixel stream matched for 6,499,480 bytes (SHA-256 `94cdcacf3663c1be2fbb30e616ba7d31dc3ad57d730fd9dd0063215367483721`). This samples scene checkpoints rather than proving every frame or entire games.

The original full Showcase fixture failed in both baseline and table modes before its scene checks because it corrupted an obsolete inner save tag/length. The corrected fixture verifies committed transport tag `76435058`, length 14204, and valid-to-invalid selection before checking rejected-load isolation. Both modes then expose the same pre-existing scene-2 result: loss at tick 131 against the fixture's expected tick 150. That assertion remains intact; the focused equality fixture does not claim that full Showcase test passes or alter the outcome.

Six normal product builds passed at merged source `6f5e006d` with all 1,958 input hashes unchanged. P10 BSS/IWRAM ends were `020391d4/03004ac0`; Showcase `02036d60/03004d20`; Z9/Z10 `0203dcd8/03004bf8`. Subsequent changes to the candidate are tests, documentation, and Makefile organization; `make -n -B` P10 and Showcase compiler commands were byte-identical before/after moving the flag definitions into the tracked fragment. The previous 2054381a and current 6f normal P10/Showcase ROM hashes were byte-identical. The table adds IWRAM code as well as ROM data, so guards are required for every affected vector.

To reproduce the paired host streams with authorized prepared inputs, generate `build/generated/sc64_contact_mask_table_generated.h` with `make build/generated/sc64_contact_mask_table_generated.h`; capture the normal P10 compiler command as JSON argv, and use fresh private output directories:

```sh
python3 tools/sc64_contact_table_pair.py --profile p10 --fixture contact --p10-argv /path/to/p10-argv.json --out /new/p10-contact
python3 tools/sc64_contact_table_pair.py --profile showcase --fixture contact --out /new/showcase-contact
python3 tools/sc64_contact_table_pair.py --profile showcase --fixture scenes --out /new/showcase-scenes
```

The runner holds the shared native flock and checks at least 2 GiB free. Run `make test-sc64-contact-mask-table test-sc64-contact-mask-math` for the exhaustive pure-math checks. For the timing comparison, use `tools/sc64_timing_profile_build.py` and `tools/sc64_timing_profile_read.py` with identical frozen inputs, the retained ordinary P7 tape and two captured P10 vectors differing only by `-DSC64_CONTACT_MASK_TABLE -Ibuild/generated`; preflight the timing reader's symbols. Builds/tests/replays here used the shared flock and disk guard. No hosted Actions were run.
