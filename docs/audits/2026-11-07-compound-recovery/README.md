# HOST-only compound Flash recovery

This disabled-by-default experiment extends the Z10 compound Flash stage with a version-3 ownership marker in the isolated commit sector. It is a HOST model and actual-game codec experiment, not an ARM enablement, physical-device validation or normal save-format change. The previous 0x4a version-1 and version-2 records keep their meanings and are refused by this version-3 stage; the original 32 KiB legacy area must still be entirely blank and is never written. Existing 0x43/0x44/0x47/0x48/0x49 migration remains unqualified.

The marker reserves eight bytes after the four-byte tag. On an initially blank target, or an alternate target proven to contain a supported same-slot version-3 record, the writer verifies the isolated commit sector erased and writes the marker one byte at a time. It verifies the complete marker before erasing any data sector, writes and checks the bounded header/base/sidecars, then programs the tag last. A marker-owned incomplete write with an erased tag resumes without erasing the marker sector. A torn tag or torn marker over old data is reclaimable only after full same-slot payload checksum and detached semantic validation, plus a physically reachable marker/tag state. Unsupported committed records and unidentifiable data remain fail-closed even when their checksum is invalid. A sole incomplete payload is never promoted: a retry writes the caller's current payload instead.

The marker is a reserved format-ownership contract, not a cryptographic signature. A foreign *uncommitted* image deliberately imitating its reserved marker cannot be distinguished from an owned interrupted transaction. The protocol assumes exclusive access and a backend that stops mutation after an uncertain timeout. Same-slot semantic proof is performed before outgoing game data are serialized, because that proof uses candidate scratch. Immediately before the first erase **or program**, the writer reselects using cached descriptors and rechecks a streaming fingerprint of the owned physical span and the outgoing source hash; it does not invoke the scratch-mutating decoder. These hashes detect accidental changes and are not collision-resistant authentication.

At tested source `29bfa3ec43a18268e8cd97596d48a252ef626061`, strict ASan/UBSan HOST qualification passed:

- Actual Z10 game saves with two committed slots were cut at marker, commit-sector erase, data-sector erase, metadata, header, base, tail, commit tag and verify-read boundaries. In each case the previously selected winner and a snapshot of actors, buildings, controllers, Scarab payers, Q8 debts, research levels, Yamato shots, impact queue, towns and wallets remained unchanged on failed save. A fresh process loaded the winner, retried the save, and another fresh process loaded the result. A first-save cut after metadata likewise recovered through fresh processes. An externally simulated marker change just before marker completion caused refusal before any erase or program.
- A small strict 1→0 model exercised 116, 116 and 117 program/erase cut positions, and 1,557, 1,560 and 1,627 read-call cut positions, for first-write, blank-alternate and previously owned-alternate cases. Each interrupted case retried; existing winners and legacy bytes were preserved. It also exercised 2,048 marker-program byte/mask cases, 1,024 partial tag-erase byte/mask cases, 2,048 partial marker-erase byte/mask cases and 459 distinct uncommitted-A/current-B retry cuts. These are bounded single-byte mask cases, not an exhaustive enumeration of all multi-byte physical erase patterns.
- Separate model checks passed an exact 28,656-byte payload, overflow refusal without mutation and sequence wrap. The real game fixture retained training, inside, fresh-release and moving Scarab fresh-load coverage, including exact waypoint/motion fields, current payer and packet-created half-HP debt, followed by matching impact and retirement. Its deliberately malformed candidate/fallback and stale-Yamato no-publication checks remained green.
- A genuine retained v1 image and genuine v2 committed and metadata-partial images were refused without erase, program, live publication or byte changes. Their SHA-256 values are respectively `e80794c9f76891c237a0ffee6c990dd92faabd85785ae57c52e61d28537f22ae`, `8c2a9bfb136612883fd75ae1ab1214c12ecfcd1212c0a259700f4a274ef101a0`, and `d019a05b9aee0443a31aa26c34f0de1f64ecce5f607eaab9ec8d4430b89673ae`. Committed records with bad CRC and unsupported v1/v2/feature tuples, invalid marker bits, checksum-valid invalid controller or unused-flight fields also failed closed.
- The detached Z10 row-context test, prior P1 game/fault suite, original Flash journal model and source boundary passed. The final receipt SHA-256 is `9668c750c069bd33fa205cc94f2dca1faba93ab3e0a055e627f1242484c457dc`; 593 prepared private input hashes were checked before and after. Private images, generated inputs and logs are not committed.

The public optional game/model recipe is `make -f Makefile -f tests/sc64-zl-scarab-controller/Makefile SC64_AUDIO_DIR=<prepared-audio-dir> ZL_SCARAB_COVER_DIR=<prepared-cover-dir> CONTROLLER_FLASH_POLICY_DIR=<prepared-policy-dir> test-zl-scarab-compound-flash`. Additional `test-zl-scarab-compound-v1-fence` and `test-zl-scarab-compound-v2-fences` targets take separately supplied verified retained images. All native builds and tests use the project-wide lock and disk reserve.

The proof does not cover adversarial marker forgery, arbitrary simultaneous multi-byte erase subsets, concurrent writers, every legal game world, maximum actor/impact states in the game codec, genuine legacy migration, ARM stack/RAM, guest behavior, Flash device identity or physical timing. A version-2 metadata-only partial record has no version-3 marker and intentionally remains fail-closed; recovery is not retroactively inferred. These gates remain open before normal use.
