# Owned stopped-child diagnostic prototype

This isolated prototype changes the existing SIGXFSZ handler to write its bounded 40-byte host register record, send SIGSTOP to its own process, and exit if externally resumed. The supervising wrapper detects the owned child's stopped status via `waitid`, runs `/usr/sbin/lsof` for that PID only, then kills and reaps the still-stopped child without SIGCONT. A dedicated lsof child has its own 64 KiB file-size limit, a maximum two-second deadline, and is killed and reaped on timeout or exception. The existing parent deadline and all emulator/file limits remain unchanged; its file uses part of the existing miscellaneous-output allowance. A low remaining deadline skips inspection. Signal masking surrounds inspector spawn and PID publication. The wrapper refuses all observer binaries until a separately qualified binary is pinned.

An asset-free fake child actually crossed the existing 2 MiB soft limit, wrote the signal record and stopped. The parent observed the stop, obtained the open synthetic target's path from lsof, verified the inspection file was at most 64 KiB, and killed/reaped the child without continuing it. Another fixture checked the cleanup path for a stopped child; on this macOS host SIGTERM itself terminated the stopped fake child, so either SIGTERM or SIGKILL is accepted, with no SIGCONT. A hung-inspector fixture checked timeout, kill and reap. Existing wrapper lifecycle tests also passed under the shared lock and 5 GiB reserve. An earlier test incorrectly expected SIGKILL specifically and failed when SIGTERM succeeded; that receipt is retained privately. These tests did not run a game or the full observer.

An lsof snapshot is read-only but lists open descriptors, access modes and paths at inspection time; it is not proof of the syscall or descriptor that caused SIGXFSZ. Permission failures, process-exit races, descriptor reuse, pipes, anonymous temporary files, kernel writes, and missing/renamed paths can prevent attribution. Inspection may be incomplete or capped and that status must be retained. No broad system tracing was used, and no native observer binary or further emulator run is qualified by these fixtures.

A separately built full observer at source `b1fcc3cc5e86f2d0b05ca650ca30f9bbb709c162` explicitly defines `SC64_OBSERVER_STOP_ON_SIGXFSZ`; wrapper pin successor `4d1fbdba9e201c7bd020a6d5348e945e3a40c482` differs only in the binary hash. Binary SHA-256 is `f626c08a64ecdfa70caf39408b53327c706834be3e80712cd09719f8dcea15be`. The synthetic signal/stop/inspector tests, framework-linked packed inventory fixture and five wrapper tests passed under the shared lock; all 12 copied upstream inputs remained unchanged. The stopped-child classification records only observed SIGSTOP; the separate signal record and lsof completion/failure/timeout/cap status must be examined independently. This qualification did not run the emulator or prove any native writer.

## One bounded native diagnostic

The one authorized fresh attempt used the pinned stopped observer and one neutral 700-step command, without requested frame or RAM capture. It reached READY and produced a 40-byte record reporting SIGXFSZ (25); the parent independently observed SIGSTOP, ran lsof for the owned PID (exit 0, 1,654 output bytes), then intentionally SIGKILLed and reaped the stopped child without SIGCONT. Child return code −9 therefore reflects supervisor cleanup, not the original signal. No frame or RAM snapshot was produced; checked ROM, executable, source and library inputs remained unchanged. The wrapper's `ok:false` also reflects its ordinary three-snapshot requirement and is not a separate diagnostic outcome. The packed pre-run inventory contained 447 entries and complete status.

The lsof snapshot contained a read/write descriptor for an Apple Metal cache `libraries.data`, size 2,424,832 bytes, already larger than the 2,097,152-byte soft per-file limit; another read/write descriptor referred to its 4,860-byte `libraries.list`. Read-only stat afterwards showed the data file's modification time predated this run, while its metadata-change time and the list modification time were in the run's minute. Those observations make the Metal cache a concrete candidate for investigation, not proof that this process wrote it, that a particular descriptor caused SIGXFSZ, or that another process did not update it. The snapshot is not a syscall trace, and external cache mutations are outside the owned-output accounting. No retry or cache mutation was performed.
