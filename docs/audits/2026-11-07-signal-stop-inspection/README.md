# Owned stopped-child diagnostic prototype

This isolated prototype changes the existing SIGXFSZ handler to write its bounded 40-byte host register record, send SIGSTOP to its own process, and exit if externally resumed. The supervising wrapper detects the owned child's stopped status via `waitid`, runs `/usr/sbin/lsof` for that PID only, then kills and reaps the still-stopped child without SIGCONT. A dedicated lsof child has its own 64 KiB file-size limit, a maximum two-second deadline, and is killed and reaped on timeout or exception. The existing parent deadline and all emulator/file limits remain unchanged; its file uses part of the existing miscellaneous-output allowance. A low remaining deadline skips inspection. Signal masking surrounds inspector spawn and PID publication. The wrapper refuses all observer binaries until a separately qualified binary is pinned.

An asset-free fake child actually crossed the existing 2 MiB soft limit, wrote the signal record and stopped. The parent observed the stop, obtained the open synthetic target's path from lsof, verified the inspection file was at most 64 KiB, and killed/reaped the child without continuing it. Another fixture checked the cleanup path for a stopped child; on this macOS host SIGTERM itself terminated the stopped fake child, so either SIGTERM or SIGKILL is accepted, with no SIGCONT. A hung-inspector fixture checked timeout, kill and reap. Existing wrapper lifecycle tests also passed under the shared lock and 5 GiB reserve. An earlier test incorrectly expected SIGKILL specifically and failed when SIGTERM succeeded; that receipt is retained privately. These tests did not run a game or the full observer.

An lsof snapshot is read-only but lists open descriptors, access modes and paths at inspection time; it is not proof of the syscall or descriptor that caused SIGXFSZ. Permission failures, process-exit races, descriptor reuse, pipes, anonymous temporary files, kernel writes, and missing/renamed paths can prevent attribution. Inspection may be incomplete or capped and that status must be retained. No broad system tracing was used, and no native observer binary or further emulator run is qualified by these fixtures.
