# Guardian morph IWRAM placement probe

This default-off experiment adds `SC64_GUARDIAN_MORPH_NOINLINE_PROBE` to move only `race_guardian_morph_tick` out of an inlined caller. The function is called from the Guardian Cocoon branch of `update_orders`; it does not move the order loop itself. Source base: `bd4dec9bdad88eb6d9ae70b90e3ea4f8908fd75c`; change commit `7662524c`. With the probe explicitly enabled, the staged Z7-derived ARM build reached the linker and failed the unchanged IWRAM assertion. The end moved from `0x030052b8` to `0x03005208`, a reduction of 176 bytes, but remains 520 bytes above `0x03005000`; because the assertion is strict, at least 524 more bytes must be removed to pass. BSS end remained `0x0203d4b4` and passed its existing limit. The failed link is not a usable ROM.

Compiler `.su` records report `update_orders` at 72 bytes before and 64 bytes after, and a separate 32-byte `race_guardian_morph_tick` frame after. These are individual static frame estimates, not nested worst-case bounds or observed stack high-water. Correctness parity, paired runtime cycle measurements and full nested stack analysis remain necessary before considering promotion. No performance improvement or successful Z7 qualification is claimed.
