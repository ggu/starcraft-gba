# Actual campaign research HOST stage

This default-off experiment connects the previously inactive human binding and
campaign policy to the actual P1–P10 initialization, Forge/Core menus, payment,
update, cancellation and existing weapon/armor/range routes. It is not a normal
ROM feature, complete research/combat implementation, or campaign win proof.
The qualified runtime is `13953e8225b1c0297966e20e19d0b7f5d5d10b80`.

`SC64_EXPERIMENTAL_RESEARCH_CAMPAIGN_JOBS` requires HOST and the existing job
stage. Combining it with the custom active-job journal flag is a compile-time
error: no campaign job namespace or detached campaign decoder is authorized.
In this configuration the existing job-stage fences refuse all save/load
entry points before SRAM access. The older four-flag custom ARM preview is a
separate configuration; its earlier evidence is not this stage's evidence.

The live controller identity comes from the canonical selected map, its human
slot and the actual `race_campaign_owner` role resolver. P1–P9 bind source 7,
P10 binds source 1, and both use compact SIDE/global human wallets. Retained
actor origin is not the payer: the fixture includes the real authored P1
rescue of its source-owner-1 Nexus. Enemy and ambiguous current-controller
bindings remain unsupported. This is not a claim that every transfer, source
permission or enemy upgrade is implemented.

New-match initialization validates all six rules before publishing source
initial levels. Admission honors scenario maxima and supported source-default
prices, alongside the existing exact producer, power, prerequisites, duplicate
and original-payer checks. Source prerequisite loss does not cancel paid work;
power loss pauses it. This stage retains stock/project time scaling rather
than claiming measured N64 timing. The authenticated private policy header has
SHA-256 `3b7ece6374fbcc26d4ebd312b5c943adb7f1313e1613f5db262e7c03e092065e`;
no ROM-derived header or proprietary asset is committed.

Independent review found that the older generic Weapons/Armor commands could
still buy flat-price bonuses and bypass family permissions. New generic Protoss
purchases are now refused in both staged custom and human campaign contexts.
The non-producer menu shows SELECT LAB with no bogus price. Genuine old
completed/pending generic jobs remain migration floors; their state is not
silently rewritten or added twice to typed bonuses.

The focused actual-P10 ASan/UBSan fixture passes: all ten real campaign map
initializations seed source-owned levels; an authored P1 rescue and Forge scene
uses B/A to purchase, advances through the shared game update, pauses without
power, cancels/refunds, completes and affects the ordinary weapon-level query.
It checks source caps, human versus enemy routing, malformed mode rejection,
new-custom reset, and unchanged SRAM when save/load is refused. B/Down/A
non-producer tests reject both generic purchases before a typed job, at the
scenario cap and in custom play without changing bank, levels or pending work.
The existing P10 custom job/lifecycle sanitizer fixture also passes with the
campaign flag absent. These are authored HOST scenes, not ordinary full-match
play, guest execution, or hardware qualification.

All 593 prepared input hashes remained unchanged in each qualified run.
The new campaign fixture passed in 18.09 seconds; the existing custom fixture
passed in 18.08 seconds. An exact current normal P10 production link, with
research flags off, passed unchanged guards and reproduced the qualified
`8e9f0a0a` normal ELF's raw binary byte for byte (SHA-256
`4daff951925f40a9745f41b025564e22ed1138d560a623c576b7c30d43c482a0`).
Only this normal profile was relinked here, not a combined six-profile claim.

The first fixture build failed because the test named the wrong legacy entry
point and lacked its HOST SRAM translation unit; both fixture errors were
corrected without relaxing runtime checks. A first normal control failed when
its compiler intermediate hit an overly small 64 MiB per-file limit. Only that
failed normal build was rerun with a 256 MiB intermediate limit, the same frozen
source/inputs and the shared native lock; it then passed the byte comparison.
Private receipts/failures are `.local/research-campaign-runtime/`.

To reproduce with independently authenticated prepared inputs:

```sh
make -f Makefile -f tests/sc64-research-campaign-runtime/Makefile \
  SC64_RESEARCH_COVER_DIR=<prepared-cover-dir> \
  SC64_PR_POLICY_DIR=<authenticated-private-policy-dir> \
  SC64_AUDIO_DIR=<prepared-audio-dir> test-sc64-research-campaign-runtime-p10
```

Run native jobs under the shared lock and disk reserve. Remaining gates include
campaign job journals/migration and detached context, enemy controllers, exact
fractional HP/shields and specialized attacks, all-product default/feature-on
checks, runtime stack/IRQ, ordinary campaign play and performance. Normal flags
remain off. The broader goal remains 29/30 content with incomplete campaign,
custom-game, persistence, fidelity and near-30-fps qualification.
