# T1 ordinary-input mineral orders

The T1 state-observing controller issues A on currently visible mineral fields for idle SCVs. It repeats ordinary input after a field is exhausted, without changing the original 30,000-input income budget. L cycles actual selected units for the Barracks builder, and placement checks the real UI-snapped site rather than requiring an unreachable exact cursor parity. The new assignment observes own actors and currently visible fields. The inherited combat planner still scans enemy Zerglings and the earlier nearest-patch helper without visibility filters, so the overall controller is state-observing and may use hidden information; this is not a fog-limited human policy.

On the worker-order candidate runtime corresponding to `83875b4`, the normal-input host controller won at frame 11,283 after 11,314 input updates, with 10 Marines, five SCVs and rescued Raynor. The controller's actual pause/save/restart/load round trip passed. A separately compiled host program replayed all 169 recorded held-input transitions through `game_update`, matched all 11 periodic actor/building/mineral world hashes and the final world hash `68a31535`, and reached the same outcome. This is host evidence only; no ARM replay, timing or hardware result is claimed.

Trace schema 2 explicitly declares completion and event/checkpoint counts. Its strict exporter rejects unversioned legacy traces because their completeness cannot be established, as well as missing data, invalid order and bounds. Recording is bounded to 4,096 events and 256 checkpoints; overflow returns an error without writing a trace. A two-event-cap build exercised this failure. Controller code and instrumentation do not change game time limits or mission victory conditions.

The earlier 512-event trace reached its limit and is incomplete. A later exploratory controller used 220,962 calls because exact-coordinate cursor chasing oscillated; native L cycling and snapped placement removed that inefficiency. Those intermediate runs are preserved locally and are not presented as complete replay proof.
