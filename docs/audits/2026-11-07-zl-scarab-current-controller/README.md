# HOST late-Zerg Scarab current-controller experiment

This default-off HOST experiment composes the P1/Z9/Z10 current-controller stage with the bounded paid Scarab lifecycle. A late-Zerg Reaver's verified current source slot binds directly to its town's `uint32_t` mineral wallet; it is not inferred from its retained raw origin or the collapsed ENEMY combat owner. Payer witnesses distinguish source-town from custom-owner banks. Unknown or mismatched bindings refuse payment, and an actor transfer is refused while a Reaver has unsettled paid work or any attached/outside child. Scarab children themselves cannot be transferred. A spawned child inherits its verified parent's current controller. All save/load entry points remain fenced: there is no controller or child persistence format here.

At `3dad507786d0b308a5c62ff1427aea1952eacbae`, strict ASan/UBSan HOST fixtures passed under the shared native lock with 593 prepared input hashes unchanged: the new Z10 case, the existing custom Scarab payer fixture, the P1 rescue/controller fixture, and source boundary. The Z10 fixture uses the actual descriptor's town-0 Reaver, transfers it empty to town 7, pays 15 once, rejects a queued transfer, cancels and transfers to town 2, and pays that town's 15 while retaining raw origin 0. Other town and human wallets remain unchanged. It checks child transfer refusal during training, inside and outside phases; no-ammo in-range combat does no damage; slot reuse begins unknown.

For the paid impact case, authored HOST setup removes other actor interference and selects a walkable corridor from the actual Z10 map. A stationary unarmored, unshielded 200-HP Zergling stands 48 GBA pixels from the Reaver. Actual `tick_combat` launches the paid child; source-cadence child dispatch moves it from x=320 to x=358, then the actual shared impact service resolves its packet for 100 damage and the child retires. No wallet changes follow the paid shot. This is a bounded authored clear-corridor witness, not an ordinary-input win, arbitrary-path, native timing or hardware claim.

The optional recipe is `make -f Makefile -f tests/sc64-zl-scarab-controller/Makefile SC64_AUDIO_DIR=<prepared-audio-dir> ZL_SCARAB_COVER_DIR=<prepared-cover-dir> test-zl-scarab-controller`. It requires already-prepared private Z10 inputs. The HOST vector retains normal Z10 Nydus and its guard, adds the existing BC ENERGY and YAMATO source-cadence primitives required by the Scarab probe, and excludes worker-cargo only in this isolated save-refusing fixture because those codecs cannot share the experimental namespace. It does not add unrelated BC actor-expansion flags. The vector does not enable `SC64_FACT_TABLES`; collision facts therefore use the existing reference/fallback path, not a stale generated table. No private inputs are regenerated or committed.

Earlier attempts remain recorded privately: the first vector lacked required source-cadence prerequisites; full BC actor-expansion flags tripped the unchanged Nydus six-bit count guard; an interim source profile needed an unused-parameter annotation. The descriptor has no town-7 Reaver—the authored transfer uses its real town-0 Reaver. An initial arbitrary coordinate caused the child to expire without moving, while an initial close-range detonation did not establish movement. The clear-corridor case then reached the paid impact but exposed an unrelated fixture assumption about first-free reuse after isolation; the final fixture fills earlier free slots before testing reuse.

Normal products remain unchanged and this experiment is not approved for ARM, save migration, all campaign ownership transfers, arbitrary Scarab movement, full combat, game wins, or physical hardware. Restock cadence is an authored approximation, not an observed N64 timing rule.
