# Authentic same-process hybrid candidate

This isolated candidate is unbuilt, unqualified and has not run. Its pinned 276-byte ordinary-input plan begins with the previously observed custom setup, then requests an internal transition at frontend step 4,200 and two post-transition framebuffer captures after neutral/A/neutral inputs. Those steps are not game frames. The command file is private and its SHA-256 is `b1943362dd674102b852c5c62d0de329a54cb32d28942bf564e39a26495c0205`.

At the owned `root->run()` return boundary the candidate obtains a bounded 8 MiB cache-aware view, failing on alias conflicts; calls the official in-memory synchronized serializer; selects Recompiler false; and passes the exact newly created opaque bytes to official unserialize in the same process. It checks both CPU and RSP flags, Homebrew mode and RDRAM size, obtains another cache-aware view with the same conflict guard and requires byte equality. It clears the previous GPU-ready status so subsequent ordinary input must re-establish Vulkan and render requested frames. The serializer is limited to 16 MiB in memory, and its reading constructor copies the opaque data; neither state nor RAM views are written to disk. The existing process, output, frame, deadline, reserve and lock limits are unchanged.

The source accepts no external state or arbitrary guest memory writes. Even a passing comparison would establish only these same-process cache-aware views and this hybrid continuation under the checked inputs. It would not certify Vulkan internal state, fresh-interpreter boot, actor identity, game-clock cadence or native timing. GPU reinitialization and exact rendering continuity are still experimental; a separate same-input control and visual comparison are needed. Failure/conflict aborts and remains a failure rather than an inferred result. Tests are source fixtures only until separately built and run; the binary admission pin is deliberately disabled.
