# Gated human Scarab control probe

`SC64_SCARAB_HUMAN_CONTROL_PROBE` is disabled by default and requires the existing namespace and weapon probes. It initializes a newly spawned Reaver's packed empty parent state, supplies a `BUILD SCARAB` field command for a single selected, non-transported human Reaver, and runs the existing paid production adapter once per source cadence event. A malformed surviving child that claims a reused parent slot causes the new spawn to fail; the normal spawn path clears stale target references before this check, so the failure is not claimed to be a transaction with no side effects.

The inherited adapter uses the pinned OpenBW reference already documented in `2026-10-31-scarab-training-timing`: raw 85 costs 15 minerals and takes an allocation followed by 105 source progress ticks and a separate completion call; its initial 2 HP and full shields and the unupgraded five-slot capacity are reconstructed by the bounded lifecycle. The adapter rejects unexpected training-child HP mutations rather than inventing damage/healing semantics. A command charges through that adapter and is refused on insufficient minerals or full capacity. The fixture uses a synthetic skirmish world, real spawn, actual field menu KEY_B/UP/A input, and `game_update` continuation; it checks one finished child, the bank, capacity and selection rejection. It does not establish ordinary unassisted play, campaign-map placement, native N64 fidelity, or the exact source behavior of mixed selection.

Reaver factory production is still explicitly rejected by `race_skirmish_product_admitted`. This probe does not implement parent-death or STOP lifecycle integration, capacity upgrades, full flying pathing, all save states, or parent/child cleanup on every removal. In particular, pending packets and live outside children still make namespace saves refuse. These are admission holds, not completed services. No flag is added to a production profile and no hardware or performance claim follows.

The sanitized actual-engine fixture passed on both maps under the Terran, Zerg, Protoss and Showcase vectors (four compiles, eight runs). It checks 15-mineral payment, source-cadence completion, insufficient funds, the one-inside/four-queued capacity boundary and rejection of mixed or transported selection. `tests.test_sc64_lookup_make` passed (3 tests), and the Terran and Protoss opt-in Make recipes passed. Source boundary passed; all 104 frozen input hashes matched afterwards. These are host results; ARM guards and the full default suite were not run for this checkpoint. The initial test fixture ended its match after one frame because it had no buildings; adding synthetic home and opponent bases resolved the fixture setup, and no failed run is treated as a gameplay result.
