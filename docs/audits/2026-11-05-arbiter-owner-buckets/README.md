# Arbiter aura owner-bucket traversal

The indexed P7 Arbiter aura query previously visited five compact-owner buckets in every covered cell, although its unchanged `sc64_p7_arbiter_same_source` predicate rejects targets with a different compact owner. The active target index was just built from validated owner lists, and no owner changes occur before the due-cache pass. The indexed query now visits only the Arbiter's compact-owner bucket; malformed Arbiter owners retain the original five-bucket traversal, and inactive indexes retain the original full scan. The same-source predicate still checks authenticated raw source slots, including the distinct P7 source forces 0 and 4 that share an enemy owner. The change adds no persistent storage, alters no cache/update cadence, and leaves all geometry, target order and fallback paths intact.

On 958 advancing updates of the ordinary P7 tape under the normal P10 compiler vector, a replacement-loop ARM replay averaged 2,202,586.74 cycles per full update/audio/render loop on baseline `f7f49245` and 2,197,886.42 with runtime `dac380fe`: **0.213% fewer**. All 90 sampled actor/fog/pixel/frame checkpoints and modal/count fields matched. The baseline and candidate ROMs and ELFs differ. This is one nonterminal emulator window with a replacement loop, not a physical GBA result, full mission qualification, or a claim of 30 fps.

An independent diagnostic replay of the baseline counted 48 matching-owner and 192 other-owner bucket heads per advancing update. It encountered an average of 205 matching-owner entries and no other-owner entries per update in this specific window: the measured gain there comes from eliminating empty bucket probes. In 80 independently checked synthetic aura worlds with overlapping Arbiters, the baseline diagnostic counted 2,649 matching and 10,596 other-owner bucket heads, and 1,917 matching and 2,284 other-owner entries. These counts include diagnostic overhead and do not constitute an ARM speed result.

The original f7 five-bucket runtime and candidate were independently compiled with the same extended lifecycle fixture. Under P7, normal P10 and Showcase HOST feature vectors, all paired complete Unit, Building, P7 persistent-service and due/initialized streams matched: 40,931,363 bytes, SHA-256 `288bc2b1a8bc6c901cb7395ab2785677e5babf4180e40142c316373fa89d0a29`. The fixture independently checks aura results against an all-pairs oracle across 80 randomized worlds, including overlapping Arbiters, cell/map boundaries and the raw-0/raw-4 same-owner distinction. It compares the same world through direct index, freshly built owner-list index and inactive fallback, and exercises malformed unit/building owners, invalid positions, death, transport, slot reuse, owner changes with rebuild, cache timers and malformed cache words. This is bounded test coverage, not exhaustive proof.

The first actual P10-vector fixture run failed on the unmodified f7 baseline because its old P7-only save-generation assertion expected 40. The corrected fixture asserts 47 for P10 and retains 40 for the original P7 vector; both baseline and candidate then passed. The failure log is preserved with the evidence.
