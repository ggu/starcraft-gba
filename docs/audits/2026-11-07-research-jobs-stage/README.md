# Host-only producer job integration stage

This is unfinished, default-off work and cannot be enabled in a ROM. The flag `SC64_EXPERIMENTAL_RESEARCH_JOBS` rejects non-HOST compilation and requires the existing experimental journal. It is not connected to command menus, gameplay updates, combat or save/load; no test or native result is claimed here.

The prototype reads and writes the real `Building` fields for a completed Forge or Cybernetics Core. A custom compact owner and its wallet are supplied by the caller, which must authenticate owner activity, wallet binding, power, exact prerequisite, scenario maximum and the full duplicate-job scan. Admission validates all inputs before debiting. A job stages family in `level`, original payer in `queue[0]`, target level in `queue[1]`, and remaining duration in `queue_progress`, with an empty production queue. Every tick validates the supplied payer against both the producer's current owner and staged payer. Ambiguous ownership changes fail closed; there is not yet a transfer/death/cancel cleanup or refund path. The staged fields are not an authenticated save encoding and must not be written as an active job into any journal.

Legacy generic human weapon/armor levels are floors for both corresponding typed families, not additive bonuses. A legacy job pending in the same group blocks admission; prices and target use the effective floor. Other owners must not receive the human legacy floor or pending state. There is no automatic conversion or seeding of old saves, and generic pending jobs require reciprocal blocking by the future integrated menu. Shield and range upgrades receive no invented legacy floor. This is an implementation proposal, not a completed migration policy or combat integration.

Campaign binding is absent. Raw actor origin remains trigger provenance and cannot identify a current controller after rescue/capture. Future campaign support requires an authenticated current-controller and payer mapping against the relevant live or detached mission context; collapsed enemy owners must not be reverse-guessed. The staged caller-supplied validation is not evidence that those bindings, prerequisites, duplicate scans or wallet pointers are correct in actual gameplay.

Before any gameplay or ROM enablement: independently validate job fields for each building codec and a distinct tag; implement atomic save/load preflight and old-format coexistence; establish payer and lifecycle rules for cancellation, destruction, transfer, reset and power loss; wire building-context UI and all affected damage, armor, shields, range and specialized attacks; then qualify real ordinary-input flows, unchanged legacy saves, all products, bounded memory and timing. Full upgrade gameplay, source-policy fidelity and hardware behavior remain open.
