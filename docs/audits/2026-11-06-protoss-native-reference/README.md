# Native Protoss custom reference observations

Existing fresh ordinary-input ares v148 callback run `protossstart-1` used the owned USA ROM (SHA-256 `e7d21880c13953b45b8f8db6b2b6cfa02daa29d35b23799a967e96f21001b020`), the isolated input/save/system paths and scripted `protossstart` route documented in `experiments/ares-headless/README.md`. Its manifest reported success, unchanged inputs and renderer readiness. Captures are local only; no imported graphics, audio, saves or ROMs are committed.

The setup selected Melee on Challenger, human Protoss against computer Zerg. The earliest previously inspected map sample displayed 50 minerals and 4/9 supply. On visual reinspection, callback samples at observed steps 6210 and 6570 show 66 and 82 minerals respectively and 4/9 supply, with Probes moving around the mineral line and Nexus. The latter frame SHA-256 is `b08921377abfcc5aa5933805c11f77f62219c70ca21f2430dd968385699aa84e`. There were no in-map mining commands in that route. Callback-observed steps are asynchronous emulator run counts, not calibrated game frames; this does not establish a mining rate. Nor does it establish Pylon placement, construction, power-field appearance or death-effect size.

At GBA runtime source revision `94bc` in the release checkout, `race_adapter.h` initializes custom skirmish minerals to 50. That matches the native initial-bank observation for this specific setup. This source comparison does not establish matching runtime behavior, supply, resource timing, graphics, or other races and opponents. The earlier attempted Probe selection missed; it cannot support a claim about the Probe menu. The ares renderer previously produced one transient corrupted frame, and these source-integrated captures have not been independently matched to a console.
