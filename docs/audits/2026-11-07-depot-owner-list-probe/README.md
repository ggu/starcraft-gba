# Depot owner-list probe

`SC64_DEPOT_OWNER_LIST_PROBE` is disabled by default. Within `update_orders`, it uses the existing ascending building-owner list for a cache-miss depot search only while a separate derived validity flag and `target_lists_valid` are both set and the worker owner is in range. The live depot eligibility predicate is unchanged, and invalid snapshots use the original ascending scalar scan. The derived flag is set only after list construction, cleared at orders exit and by path-grid invalidation, so an in-pass foundation spawn, building death or lift forces the scalar path for the rest of that pass. Unfinished buildings are already in the list, and completion or morph is checked live. Nydus ownership reconciliation occurs before orders; imported mission/rescue and facility flight processing run after orders. No raw-origin mapping is used.

The actual-selector ASan/UBSan fixture compared result and full route field, validity, goal, age, clock, hit and build effects with scalar selection, covering equal-distance ties, spawn, death, completion, morph, incoming/outgoing transfer fallback and malformed owner. A host-only counter confirms fast-path/fallback use. The real `update_orders` phase fixture observed the list valid at entry; a real pending Probe build spawned a Pylon inside the pass, and a later mineral worker used scalar fallback even after path-grid rebuild. The next orders pass rebuilt the list including the Pylon and used the fast selector; the validity flag cleared at both exits.
