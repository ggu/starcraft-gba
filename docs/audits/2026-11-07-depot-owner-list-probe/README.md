# Depot owner-list probe

At the original experiment `73195959`, `SC64_DEPOT_OWNER_LIST_PROBE` was disabled by default. At promotion head `48831c8e`, shared `SC64_NEAREST_RESOURCE_DEPOT` profiles enable it; `SC64_DEPOT_OWNER_LIST_DISABLED` forces the original scalar scan even if the older probe flag is present. Within `update_orders`, it uses the existing ascending building-owner list for a cache-miss depot search only while a separate derived validity flag and `target_lists_valid` are both set and the worker owner is in range. The live depot eligibility predicate is unchanged, and invalid snapshots use the original ascending scalar scan. The derived flag is set only after list construction, cleared at orders exit and by path-grid invalidation, so an in-pass foundation spawn, building death or lift forces the scalar path for the rest of that pass. Unfinished buildings are already in the list, and completion or morph is checked live. Nydus ownership reconciliation occurs before orders; imported mission/rescue and facility flight processing run after orders. No raw-origin mapping is used.
