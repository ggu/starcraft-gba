# Experimental shared research journal admission

This is a default-off experiment, not a research feature or release format. It adds no menus, combat routing or paid jobs. `SC64_EXPERIMENTAL_RESEARCH_JOURNAL` requires the normal shared-transport/worker/impact save path; unsupported actor-stage formats fail compilation. The experimental transport tag reserves byte `0x44` in bits 16–23 of the current outer tag, leaving the inner `SAVE_VERSION` and normal record size unchanged. All existing source tag bases use byte `0x43`, and existing feature selectors change only the high byte; a compile-time base/transport invariant and a namespace fixture enforce the current allocation. An earlier bit-31 experiment collided with roster tags and was replaced before promotion. Both normal predecessor tags remain recognized. The flag permits legacy reads and writes a new-tag record, so an older build will not understand the new slot. Do not use it with real saves or ship it without a separately reviewed namespace and compatibility policy.

The writer validates normal state first, then packs the 96 research bits into reserved building padding in detached `race_impact_record`. The selector validates the new tag, current inner version and transport/impact payload, then decodes the levels and clears reserved bits in that detached candidate, before all existing preflight validators. A `RaceLoadPlan` keeps the eight-owner values until the selector revalidates the original SRAM slot; publication occurs only after selection. Legacy records produce zero levels. Game initialization and each new-match initialization clear the experimental live state. Existing 5-owner custom and 8-owner campaign level domains are checked; campaign/actor ownership, active research jobs, and playable upgrades are not implemented by this experiment.

No second full record buffer is allocated. Encoding/decoding traverses the existing detached rows in place, using 12 packed bytes and a 48-byte candidate level object; the load plan also stores 48 bytes. These are source-level sizes, not a measured call-chain bound or dynamic stack high-water.

Focused synthetic-level actual-engine P10 and Z9 HOST fixtures exercise campaign and custom contexts, old-tag load, new-tag round trip, an invalid newer but checksummed record falling back to the predecessor without SRAM mutation, rejection of custom owner 5, and eight pending impacts through save/load. They use ASan/UBSan and actual release profile flags plus this explicit experiment. The old-tag record is constructed by retagging a zero-level candidate, whose payload is identical to the old encoding. These fixtures do not establish ordinary research gameplay, authentic campaign-origin research levels, complete all-mission migration, or hardware correctness. Compile and run with `make -f Makefile -f tests/sc64-research-journal/Makefile test-sc64-research-p10` or `test-sc64-research-z9`, supplying the known private input banks and delivered audio directory; serialize native work with the shared lock.

A focused P10 custom fixture additionally synthesizes one and two valid charging Yamato shots with respectively five and two pending impacts, saves at the full legal payload size and reloads both shot and impact bytes unchanged. This is a constructed host state, not ordinary-input gameplay.

All six normal experimental-flag ARM vectors linked with their guards: T, Z7, Z9, P10, Showcase and Z10. Bytes to the asserted EWRAM/IWRAM boundaries were respectively 28852/2184, 2908/336, 748/1248, 19952/1248, 29296/664, and 748/1240. GCC stack-usage output is retained in the isolated build records and is not a dynamic high-water measurement. Z9 adds 48 bytes of BSS versus its exact 94bc baseline; the other runtime and caller stack paths still need independent review.

A separate compatibility fixture compiled its producer against the exact 94bc32f8 source without the experiment and its consumer against the experimental source in a different process. Real `race_save_game` produced old-tag P10 and Z9 campaign and custom saves with generic weapon/armor levels 1/2 and eight pending impacts. The consumer loaded each, matched the selected gameplay digest and impact rows, and preserved all 32768 SRAM bytes. The four input SRAM SHA-256 values, in P10 campaign/custom then Z9 campaign/custom order, are `202c4be795ac5ab9786277963a2876da23e27d165423aad32aad1577e2df576a`, `4814066663454bc01412103331d0be97ea6647bd2b4c2db6ea8c47be82b2872a`, `445aab79efe4863cc4eb35783c0032f3545f943804dc3309df01d0f5b78e3ec0`, and `ac25f8958332a2459f7b9de99782f5f95a88edd607c13691fecfe72de60d3185`. The isolated test logs and before/after dependency manifest preserve compiler flags and input hashes. The included fixture builds through explicit `research-compat-p10` and `research-compat-z9` targets with the producer/consumer flags described in their Makefile; it needs separate worktrees, the same verified private inputs, and separate process invocations.

A same-process test loads nonzero campaign research, starts custom through the ordinary front-end, restarts from the pause menu, and starts a new campaign through the front-end. New-match `init_state` clears experimental levels, while successful load preserves them. This matches the existing generic-upgrade reset at the same boundary.

The candidate row normalization runs before existing preflight checks and operates on the detached `RaceSave` member in the existing union; its preflight and commit row decoders read that normalized candidate. The scheduler and carrier candidate scratch members follow their own `RaceSave` prefix and do not overlap its rows. The selector rechecks the original SRAM header and checksum after preparation; it does not checksum the copied scratch itself, so a concurrent transient SRAM change restored before final revalidation is an existing snapshot assumption, not a concurrency guarantee established by this experiment.

Namespace inventory checks all current historical bases and generation values 0–49 against all 256 high-byte combinations; experimental `0x44` cannot equal any historical `0x43` tag. The inventory includes the former roster collision as a regression. Only currently inventoried source tag constructors are covered; future selectors that alter bits 16–23 require a fresh allocation audit. Unsupported compact/typed width and building-count combinations are rejected by a compile-time assertion; the focused layout check compiles supported tuples and verifies a deliberately unsupported tuple fails compilation.

With the experiment disabled, fresh Terran, Z9, P10 and Showcase 32 MiB ROMs were byte-identical to the 94bc32f8 package using its delivered advisor bank and matching frozen dependencies. Those comparisons preceded only the addition of the experiment-gated layout assertion and its compile fixture; neither is present in flag-off preprocessing. Flag-on six-profile link evidence and the compatibility fixtures above are also for source based on 94bc, not for a merge with subsequent source-release commits. Re-run combined-source qualification before considering promotion.
