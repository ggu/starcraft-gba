# Authentic hybrid feasibility and pure-JIT control

An isolated pinned ares `0aafd85789215e84e1e43415c07d4c88461b7899` frontend booted the owned N64 ROM using its CPU and RSP recompilers and ordinary controller input. At an owned execution boundary it serialized the running emulator's state in memory with its official API, disabled both recompilers, and restored those same opaque bytes through the official unserializer. The restore necessarily writes emulator state; no arbitrary guest-memory writes or externally fabricated state were used. The observer reported an equal, cache-aware 8 MiB RAM view across the transition, both recompilers disabled afterwards, and GPU readiness after continuation. It completed 4,230 input steps and captured two frames. This is an authentic hybrid restore, not a fresh-reset interpreter run.

A separate visual-only pure-JIT control used the same input schedule and frame checkpoints, with only the transition marker replaced by a neutral marker. It had no RAM capture or state restoration. Both runs completed and reported GPU ready; each retained two 640×240 raw frames at observed steps 4,209 and 4,229. The inspected first frame shows a Protoss Nexus, mineral fields and a 66-mineral, 4/9-supply HUD. It was previously misidentified as Terran; that description is corrected here.

At the respective checkpoints, 129,739 and 129,620 of 153,600 pixels differ in at least one stored byte. Every differing byte has absolute difference exactly one; 222,356 and 222,159 bytes differ, with mean absolute byte differences 0.36191 and 0.36159. The frames are visually close but not byte-identical. Two matched snapshots cannot prove continuous GPU equivalence or explain the numerical difference.
