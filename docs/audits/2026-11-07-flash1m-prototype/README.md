# Flash1M transport experiment

The isolated transport is default-off and is not called by the existing SRAM backend or any game journal. It uses the two 64 KiB bank command and sector program/erase command sequences in the locally pinned mGBA `src/gba/savedata.c`, commit `26b7884` (mGBA is an independent behavioral reference, not proof of physical cartridge geometry). A strict HOST fake enforces one-to-zero programming, bounded timeout, bank crossing and sector isolation. Its ASan/UBSan check passed under the shared lock with the 4 GiB reserve. Sticky fault prevents further calls after a timeout; it does not claim automatic recovery.

The initial implementation was not ready for journal use: equality-only completion polling can report ready if a device's busy byte equals the programmed value. The later bounded experiment below replaces that polling, but still requires device-specific qualification. No device ID or geometry has been verified. The model's erase does not cover power cuts or partially erased sectors, and there is no journal implementation, migration, or atomicity proof.

A standalone test ROM contains `FLASH1M_V103` and no `SRAM_V` string; it exercises bank-crossing guest writes. The initial two mGBA executions failed: the guest reported program failure and mGBA logged accesses to non-existent save memory, including when the test-only runner received a separate erased 128 KiB temporary save. Neither detection nor persistence is established. Logs and builds are in ignored `.local/q8-proof/`; the 128 KiB runner is an isolated modification of the existing headless runner, not a shipping tool. The original 32 KiB SRAM release path remains untouched. Changing save type on actual EverDrive hardware and importing old saves are untested.

The original test header used game code `F1MT`. The pinned mGBA `GBAOverrideFind` treats unrecognized codes beginning with `F` as Classic NES EEPROM; the initial failure was therefore an emulator override, not proof that Flash commands or a signature failed. With `X1MT`, the isolated mGBA runner automatically detected Flash from the first guest bus command and bank switch, the test ROM reached status `0x600d`, and the runner exported 131,072 bytes. This establishes command-based mGBA detection, not signature-based detection on other devices. A separate forced-Flash1M mGBA reader loaded an exported 128 KiB image in a fresh process, reached `0x600d`, and re-exported byte-identical contents. An unforced fresh-process temporary-save attempt instead crashed with signal 11; its cause remains open. Forcing the emulator model is test configuration, not a guest memory write or hardware proof.

The prototype now checks two DQ6 samples and, for byte `0x5f`, requires a different unchanged byte in the same sector as a witness, since this mGBA version returns constant `0x5f` while settling. If no such witness exists, it refuses before programming. A strict HOST model covers both eventual completion and a stuck `0x5f` case, which times out without further commands. A guest write of `0x5f` succeeded in the forced and auto-detected mGBA runs. DQ6/data polling is a standard parallel-NOR technique, but exact part identification, timing, reset behavior and 4 KiB erase geometry are not yet verified for the user's cartridge; see [Infineon's data-polling description](https://community.infineon.com/t5/Knowledge-Base-Articles/Data-polling-in-Infineon-Parallel-NOR-Flash/ta-p/443655). The witness scheme deliberately fails closed on a sector with no usable witness and is not a production-ready general Flash1M driver. No claim of power-fail-safe journaling or direct migration from an SRAM-configured cartridge follows from these tests.

A follow-up unforced fresh process used the same 131,072-byte input, SHA-256 `67c7e5f7888afcd70282180ae98515e89f90abcabdfd21cb7dbb0ce0ed71dcef`, copied into mGBA's writable `VFileMemChunk` before `loadTemporarySave`. The original file remained byte-identical. Guest commands produced mGBA's logged Flash detection, 512 Kbit to 1 Mbit bank upgrade, final savedata type 3, successful `0x600d` read, and a byte-identical 131,072-byte export. There was no `GBASavedataForceType` call in this test and no debugger guest-state write. The earlier O_RDONLY temporary-file test crashed; the pinned mGBA `_flashSwitchBank` requests a writable remap when expanding, so the differing VFile map capability is a supported explanation, not a proved root cause. This is an isolated emulator-tool workaround; it does not prove EverDrive behavior or the correctness of any future game journal. The test-only runner source, exact inputs, output and logs are retained in `.local/q8-proof/`.
