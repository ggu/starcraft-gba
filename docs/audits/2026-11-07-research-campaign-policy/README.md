# Protoss campaign research policy groundwork

This inactive source-only adapter combines an explicitly authenticated live or detached campaign controller context with the optional private all-campaign policy from the authenticated generator in PR #327. It supports the unique current human SIDE in P1–P10 only: source controller/payer 7 for P1–P9 or 1 for P10, and compact human wallet slot 0. The wallet slot denotes the engine's global human minerals and gas, not the AI bank array. Raw actor origin is deliberately not consulted: rescue and capture can retain the original owner. Enemy current-controller and payer identities remain unsupported; compact ENEMY is never reversed to a guessed source slot.

The caller must authenticate the mission identity, descriptor and runtime role map against its own canonical live or candidate context, and authenticate the private policy table before exposing it. The adapter checks the unique human role, chapter and owner, validates family bounds and scenario maximum/initial levels, and refuses non-default pricing overrides. With no private generated table the public default view is null and policy requests fail closed. Quotes use the existing source-derived price and project time scaling; this is not a native timing claim. This pure query does not check producer identity, prerequisites, power, wallet, duplicate jobs, journal validity or a physical menu; it does not pay, start, progress or save research. Only rules returned from the authenticated query are suitable for its quote function.

The private table used for the fixture was generated by `5b733f166d7091936584db0a08837e4226161ebe` from the authenticated owned ROM; its SHA-256 is `3b7ece6374fbcc26d4ebd312b5c943adb7f1313e1613f5db262e7c03e092065e`. The existing generator requires 30 unique authenticated CHK catalog entries, follows pinned OpenBW base/expansion precedence and marks unsupported custom price/time overrides; these source facts do not establish N64 behavior. No proprietary policy header is committed.

The asset-free ASan/UBSan fixture exercises all ten mission indexes, source owner 7 versus 1, policy floors and caps, default cost quotes, malformed rows, unsupported pricing, wrong modes, ambiguous roles and nonhuman rejection. The prepared P10 HOST fixture initializes all ten actual campaign maps and checks generated owner-specific values, human wallet accessors, P1's authored rescue of a raw-owner-1 Nexus into SIDE, and a captured P1 context while unrelated live globals name a different mission. Position and wallet values are fixture setup. This is neither gameplay completion nor proof that any future detached decoder authenticates its own context. No runtime research, journal namespace or save code is changed.

Public commands are `make test-sc64-research-campaign-policy` (asset-free) and `make test-sc64-research-campaign-policy-game SC64_PR_POLICY_DIR=<private-policy-dir> SC64_PR_COVER_DIR=<prepared-cover-dir> SC64_AUDIO_DIR=<prepared-audio-dir>` (requires previously prepared P10 inputs and authenticated private policy). The qualified HOST run held the common native lock with a 5 GiB reserve and checked 41 private inputs unchanged; it used the same compiler flags and sources as the public prepared recipe. An initial attempt using a full production prerequisite list stopped before compilation because an unrelated prepared header was absent; the focused recipe was then used and that failure remains in the private log.
