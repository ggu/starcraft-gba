# Shared-actor ARM stack review

This is a bounded read-only review of the separate experimental rare-dispatch plus diamond-placement source at `74d0bad0200e64ef290f1b0c71a04ae9c63c425b` (runtime change `9d87a539`). It uses the three linked `.elf`, `.map` and GCC `.su` outputs in the private `.local/rare-actor-diamond-iwram-probe` qualification directory. It is not a runtime high-water measurement, an exhaustive whole-program stack bound, a campaign-save qualification or a release recommendation. No emulator or new build was run for this review.

`common/start.s` sets banked IRQ SP to `0x03007fa0` and system SP to `0x03007e00`. The linker requires `__iwram_end < 0x03005000`; the interval from that guard to initial system SP is 11,776 bytes. The guard is an address reservation, not a measured stack margin. IRQ and system modes have separate SP registers but use the same physical IWRAM; IRQ stack growth can meet the main stack. The initial SPs are only 416 bytes apart. The BIOS dispatcher, exception entry and any overlap must be considered, not simply added to system `.su` frames as if all code used one stack.

The ELF hashes were Z7 `f92afc50e43f63f4b93207886cc06458ca2bb7a1c68885c08dde3a4fe967aff2`, Terran `9fdd906ee79453b810803cbb12a743098681999e086476934106caeb133f4139`, and P10 `41b6d29eb1c216ccaeb9e44f0378ea45abd199f372664954b5ebe313642af3ec`. Every emitted `.su` row in these products is marked `static`; no linked `malloc`, `calloc`, `realloc`, `free` or `alloca` symbol appeared in these ELFs. Neither observation establishes a bound for indirect calls, BIOS code, compiler helper routines, assembly, startup before instrumentation or unexercised paths.

## Connected paths and limits

Disassembly shows `main -> game_update -> game_update_step -> field_ui_pause_input` and pause input calls save/load. In Z7, a load calls `race_worker_cargo_select -> save_select_prepared -> save_prepare_selection`; the last invokes its supplied callback through a `bx r9` trampoline, not a direct named branch. Source binds it to `race_worker_cargo_prepare_selected`, whose disassembly calls the Z7 and Z6 legacy validators on separate branches. These validators are not simultaneous frames and must not be summed together. Their emitted Z7 frames are 3,240 and 3,192 bytes; save and load themselves are 648 and 504 bytes. The often-cited 2,488-byte save, 2,328-byte load and 1,520-byte preflight frames belong to Terran, not Z7.

One connected Z7 load/callback branch has individual reported frames 56 + 72 + 160 + 8 + 504 + 56 + 112 + 32 + 232 + 3,240 + 376 + 20 = 4,868 bytes through the Z7 validator, Guardian authenticated decoder and `sc64_derived_get`. A syntactically connected Terran save/previous-record-selection/preflight/late-validator sequence adds to 4,976 bytes before deeper calls; a P10 sequence through preflight and the P6 validator adds to 4,408 before its descendants. These are sums of selected linked-call frames, **not conservative whole-program bounds**: branch reachability for particular authenticated records, nested callees, veneers and interrupt effects remain to be resolved. Other paths, including update, render, initialization, mode-specific validators and callback targets, can exceed them. In particular, the full-stage writer rejects campaign mode at the entry to `race_save_game`; it is incorrect to claim an ordinary current campaign save reached the writer's later validators. Previously created valid campaign records may exercise legacy validation when loading or when selected as previous records; test the actual tag and mode paths.

For the rare update branch, the Z7 compiler reports `update_orders` 56 bytes, `sc64_rare_actor_dispatch` 32 and `race_scarab_control_dispatch` 208; its other callbacks and deeper callees add to that selected chain. This is not a maximum for `game_update`. The Z7 audio IRQ's C frames report 16 bytes for `audio_irq`, 112 for `audio_vblank`, 48 for `audio_decoder_run`, and up to 88 for a decoder specialization, or 264 bytes on that particular linked chain before BIOS dispatcher and other unknown overhead. ARM/Thumb veneers and banked-SP use must be checked, including interrupt nesting rules and any BIOS stack use, before treating the 416-byte initial separation as sufficient.

## Runtime qualification plan

The existing Z7 input-only replay paints from `0x03005000` to at most 256 bytes below its current system SP and reports the lowest overwritten paint (`tests/sc64_z7_arm_replay.c`; `tools/sc64_z7_arm_replay.py` checks positive, monotonic untouched bytes). It starts before `gba_init`, which covers more initialization than a post-init paint, but does not cover earlier startup, every possible path, or the IRQ stack region above `0x03007e00`. A paint marker can also miss writes that restore the pattern or occur in unpainted gaps. An unaltered historical replay was compiled under different flags and cannot establish this candidate's high water.

Before running any new probe, review an instrumentation design that retains the original linker guards, masks IRQ safely during any IRQ-band initialization/read, avoids BIOS-reserved words and active stack frames, captures system and IRQ low-water separately, and documents BIOS dispatch assumptions. Build matched candidate and diagnostic ROMs with the exact same runtime feature vector and source; compare ordinary-input traces and observed outcomes with instrumentation off/on, and verify placement, stack bounds, and unchanged guard/link margins. Use real menu input and genuine SRAM from the same profile for a custom save and fresh-process load; also load authenticated legacy campaign records to exercise validators and demonstrate the expected current campaign-save rejection. Include representative busy orders and rendering, ongoing audio/interrupts, full save/load callbacks and error/fallback paths. Preserve ROM/input hashes, actual SRAM records, per-phase high-water and outcome checks, and use the shared native lock and disk guard. Do not inject world state or treat a seeded synthetic journal as a guest save.

Even a passing bounded replay would qualify only those paths and sampled conditions. It would not prove arbitrary save-state stack use, all interrupt combinations, future builds or physical hardware behavior. The campaign writer and other actor, art, correctness and performance gates remain open.
