# Experimental read-only native actor observer

This is an unqualified source-only observer, not an actor layout, simulation clock or order-cadence result. It is separate from the existing interactive frontend. No guest-memory write, MMIO read, savestate import or gameplay injection is exposed. The dedicated frontend forces `Recompiler=false` and rejects a still-enabled CPU recompiler or Homebrew Mode after power and at each snapshot. It adds the pinned ares Gamepad `B` node to the preexisting ordinary input mapping; whether B is the desired in-game STOP command must be established visually, not inferred from the SDK name.

A command with capture value 2 takes one cache-aware full RDRAM sample after a bounded `root->run()` chunk. The requested span must fit the actual 8 MiB allocated RDRAM and never wrap. Each byte reads a valid matching CPU D-cache line or direct RDRAM on a miss, without a bus/MMIO call; both possible virtual-index aliases are checked and a duplicate hit aborts rather than guessing. The sample is CPU-cache-aware, not an atomic snapshot of asynchronous DMA or graphics. A private record pairs the callback step, current CPU PC and CPU thread clock with each sample; these are labels and are not independently validated simulation clocks or writer PCs. Controller and framebuffer records retain the existing bounded callback semantics.

The frontend permits at most two 8 MiB RDRAM samples and 2 MiB of copied frames per process, with the existing 14,000-step, 180-second, input-event and callback limits. The 32 MiB ROM copy, 16 MiB snapshots, at most 2 MiB frames, bounded metadata and 1 MiB stdout/2 MiB stderr budgets fit the 64 MiB output ledger; the wrapper also records total output and reserves at least 1 MiB for its final manifest within the 64 MiB limit. A cache conflict can partially fill only the private scratch buffer, which is discarded without writing a snapshot. Command mask bits C-Down=256 and B=512 differ from their recorded input IDs 1024 and 2048. The wrapper checks pinned ROM, source, library and frontend hashes, uses isolated fresh saves, takes the common native lock and checks at least 5 GiB free. The attempt below produced 16 MiB of snapshots and 52,885,023 total recorded output bytes within its 64 MiB per-run cap. No machine-readable task-wide ledger was located, so no remaining task-wide budget is inferred. Files remain private. Failure or partial output is not evidence of actor identity.

An asset-free ASan/UBSan fake-reader test verifies normal mixed cache/RAM reads, end-of-range and overflow rejection before any callback, null/zero/oversize rejection and duplicate-cache conflict refusal. It does not prove ares ABI, real cache coherence, selection/STOP semantics, DMA quiescence, record identity, writer PC or timing. The isolated build and first observation are recorded below; independent review of the source and actual ares behavior remains necessary. Source records and hashes must be checked before and after any subsequent build or run.
