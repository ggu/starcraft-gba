# Current contact-class cache feasibility

Current normal P10 uses `SC64_CONTACT_CACHE`. Its step-clear and one-pass blocked-steering mask both call `sc64_contact_class_for(c->type)`, which already maintains a 256-byte lazy cache keyed by type. The cached byte contains only type-derived radius, flying and ignore/burrow-capability facts. Invalid or unrepresentable classes retain the reference predicate. P6 burrow state additionally reads the candidate's live raw type and flags; liveness, transport and Scarab presence remain live predicates. Owner is not an input to this class.

The normal legacy spatial bucket index rebuilds at the start of orders and maintains head, next, previous and cell state for insertion and movement. Those arrays are live linked-list bookkeeping, not free per-slot bytes. Existing `SC64_COLLISION_CLASS_CACHE` uses a separate per-slot array, but it is explicitly incompatible with `SC64_CONTACT_CACHE`; it cannot simply be switched on beside the current implementation. A new one-byte per-slot class alone would become stale when a live slot changes type without changing cell: Egg birth assigns `q->type=q->target`, and Guardian morph explicitly preserves the spatial index while changing type and raw identity. Spawn/slot reuse, campaign initialization and load, index invalidation/fallback and any additional enabled morphs also require coverage. A class-plus-live-type tag avoids relying on every mutation hook but costs approximately 720 bytes for 240 slots and still requires reading and comparing the live type. The already-existing type cache needs no actor-lifecycle invalidation, so a per-slot duplicate is not assumed to save cycles.

The optional four-entry contact-mask memo is a different whole-query cache with explicit invalidation; the proposed per-slot class cache must not assume that enabling or invalidating it updates a new array. The currently measured P10 diagnostic attributes approximately 158,000 nested mean cycles to the full contact-mask path and 88,000 to step-clear; those values do not isolate type-cache lookups. No occupancy, class-hit or cycle evidence here establishes a per-slot cache gain. Any future prototype needs an independent live-type/reference oracle, mutation and fallback coverage, ordinary-input paired cycle evidence and unchanged guards across all normal products. No new cache, actor cap, update cadence or save field is introduced by this audit.
