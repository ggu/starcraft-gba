# Standalone Flash1M journal integration experiment

This branch connects the experimental banked transport to the reviewed isolated-commit-sector journal only in a standalone test ROM and strict HOST model. It does not change the normal game backend, save selection or production flags. The retained 32 KiB legacy area is read but never erased or programmed; two new 32 KiB slots use separate 4 KiB commit sectors and support payloads up to 28,656 bytes.

At runtime `74286fee`, ASan/UBSan tests passed for bank crossing, 1-to-0 programming, bounds, sticky timeout and a whole 4 KiB sector of `0x5f` bytes. The strict Flash-command model and real journal wrote two full-size all-`0x5f` payloads while retaining the entire legacy area. The previously reviewed journal model additionally passed 685 write-boundary cuts and 1,024 partial commit-tag erasures. Test-only successor `7515fd69` added eight command-level program-interruption cases: after emulated power reset each selects either the previous complete record or a complete successor, while preserving legacy bytes. This is not exhaustive physical-device fault injection.

A pair of freestanding GBA test ROMs passed the unchanged RAM/stack linker guards and use `FLASH1M_V103` with no `SRAM_V` string. Unforced pinned mGBA 0.10.5 detected Flash from guest commands, switched from 512 Kbit to 1 Mbit at bank selection, and wrote two full 28,656-byte records, each entirely `0x5f`. The first 32,768 bytes were an unretagged earlier genuine Z1 HOST-produced journal (SHA-256 `befe89b9c3ade22d66d86a847dc1838b06345304870c3d165135c28e2b59e341`) and were byte-identical afterward. A fresh unforced process imported a writable in-memory copy of the resulting 128 KiB test image, detected/upgraded the Flash model from guest commands, read the second full record and exported the whole image byte-identically (SHA-256 `79808c3b4fa37099e5e328fdc8e33cd25021597f887fcb660d3cbffe0ba66cbc`). No game SRAM was imported into a guest: the original is a HOST-produced private test journal. This is a synthetic standalone test, not ordinary gameplay.

Write ROM SHA-256 `b19a87d3cdb3b2c6a3235d5c774f26b5d31aebff5d53da972dd246e23e9f4326`; fresh-reader ROM `0292d61a53239a11e18258ff92cae2a06b41b65ce5d5f12c8d366651c45ddde1`; unforced test runner `0180213907a96a91f0825098b6449f65d685f734af80f430836dddb31fa8e436`. Runtime source hashes, failed first freestanding build, ARM objects, private seed/output images and logs remain in ignored `build/flashproof/`. Runtime sources and 11 build inputs were checked before and after the emulator run. The earlier O_RDONLY temporary-save mGBA failure and its writable-copy workaround remain documented in the earlier Flash audit.

The DQ6 toggle and data readback loop no longer depends on finding a different byte in the sector. The ROM sets a 256-read minimum wait only to accommodate the pinned mGBA model's constant busy byte; this is not a physical device timing guarantee. Exact supported device ID, 4 KiB sector geometry, timeout/poll/reset rules, real-device command behavior, arbitrary power loss, Flashcart save-type detection and migration from an SRAM-configured cartridge are unqualified. mGBA uses assignment for programmed bytes, so only the strict HOST model tests 1-to-0 constraints. Do not integrate this driver into a shipping journal until those gaps and the complete product/save compatibility matrix are resolved. The asset-free HOST model can be repeated with `make -f tests/gba-flash1m-integrated/Makefile test-gba-flash1m-integrated` under the shared native lock with at least 4 GiB free.
