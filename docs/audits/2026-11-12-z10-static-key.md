# Compute the exact Z10 terrain key once

Z10 was comparing its static object roster before restoring cached terrain
and again before capturing a redraw. The draw pass does not change the
roster or fog between those points. Use the existing `SC64_RENDER_KEY_ONCE`
path so both operations use the same generation. The cache, sprites, fog,
simulation and save format are otherwise unchanged.

Three diagnostic normal Z10 cartridges at runtime base `20469c2` compared
the original path, one key scan, and one scan plus a local tile-repair probe.
All replayed ordinary input through a fresh process from the same 32 KiB
SRAM exported by the normal ARM cartridge. All 83 game checkpoints
(including raw units, buildings and minerals), nine modal dismissals and
24 drawn pages, palettes, camera and fog samples matched. Each won at frame
59,997, call 61,938, with zero mission faults. The same three builds matched
64 sampled states and 12 drawn pages/palettes/fog samples on a three-AI
custom battle. These are emulator guest cycles, not a hardware frame rate.

| 1,000-call window | Original mean loop cycles | One scan | One scan plus repair |
| --- | ---: | ---: | ---: |
| Z10, calls 19,000–19,999 | 1,859,238 | 1,833,531 (−1.38%) | 1,828,248 |
| Z10, calls 35,000–35,999 | 1,853,350 | 1,823,777 (−1.60%) | 1,823,548 |
| Three-AI custom, calls 10,860–11,859 | 1,337,967 | 1,321,306 (−1.25%) | 1,327,549 |

Tile repair reused more pixels but still captured the whole band on a
miss. It repaired 188 and 142 calls in the campaign windows, and just 11
in custom play. Its per-slot comparison and extra work recovered nearly
none of that cost in the second campaign window and raised mean custom
cost by 0.47% relative to one scan. Do not ship the repair. Reconsider only
if a candidate can avoid capture work as well as the redraw.

One scan leaves diagnostic BSS unchanged (231,992 bytes), and raises text
by 72 bytes. The current battle windows are still far above the 561,792
cycles needed for a 30 fps update cadence. The largest remaining observed
stalls are in simulation; this change does not address them.
