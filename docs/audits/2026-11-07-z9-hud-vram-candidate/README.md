# Z9/Z10 page-resident HUD: source-only candidate

The smallest isolated memory experiment is to add only `-DSC64_HUD_VRAM_BANDS` to each exact Z9 and Z10 vector, with the same source, Q8/jobs/Flash flags and inputs. It changes no actor, impact or memory guard. Existing vector receipts for `417dea6c` contain `SC64_NO_FRAME_CLEAR`, `SC64_HUD_BUFFER_REUSE`, `GBA_SCENE_CLIP` and `SC64_TERRAIN_SCROLL`, but not `SC64_HUD_VRAM_BANDS` or `SC64_TERRAIN_CACHE_VRAM`. Under these prerequisites, `game.c` replaces the 240x12 and 240x40 byte EWRAM HUD copies (12,480 bytes gross) with per-page version/generation words. Exact linked savings and IWRAM/stack effects remain to be measured; do not extrapolate the old 196-byte Z9/Z10 guard margin to the combined successor.

The two Mode 4 framebuffers start at `0x06000000` and `0x0600a000`; each displayed 240x160x8 page occupies 38,400 bytes. Page-band reuse holds HUD pixels within the two existing pages, not in new VRAM. `gfx_begin_preserve()` selects the back page without incrementing its clear generation; a full clear increments the selected page generation, and `draw_hud` compares both page versions and generation before retaining, copying the matching front band via DMA3, or redrawing. Scene clipping restricts map draws to rows 12–119. Pause panels, out-of-panel minimap dots/frame and the Showcase label invalidate the bottom band. Text boxes are restricted to rows 14–71, inside the map, while result panels examined occupy rows 30–115. Title uses full clear, which invalidates the affected page through its generation. These are source findings; actual Z9/Z10 menus, triggers, display transitions and any effect that touches HUD rows require pixel tests.

The audio arena is the separate 2,560-byte gap `0x06009600..0x06009fff`; mixer/decoder data and the bounded game audio snapshot use it. The proposed HUD-only flag does not consume it. The optional terrain candidate instead uses mapped OBJ tile VRAM `0x06014000..0x06017fff`; `sc64_obj_vram.h` shares that region with the P7 projectile arena and rejects the experimental tile renderer. Text-box state ends at `0x06014000`, immediately before the OBJ region. The retained Z9/Z10 argv has no explicit `SC64_P7_PROJECTILES_ENABLED` or `SC64_TILE_RENDERER`; verify derived macros and link-map ownership before assuming all 68 terrain rows are available. With no projectile owner, `SC64_TERRAIN_CACHE_VRAM` would move 16,320 bytes of the 25,920-byte terrain band to OBJ VRAM. HUD and terrain flags should be paired separately first; neither is enabled by this audit.

Older evidence in `2026-10-28-render-caches` includes 22 host pixel comparisons for Z1–Z6/P7/Terran, poisoned pages, transitions and one Z1–Z6 ARM workload; `2026-10-31-showcase-hud-cache` contains a separate Showcase paired run. Neither qualifies Z9/Z10, the current combined Q8/Flash source, all modes or an FPS target. Before promotion, compare identical source, frozen assets and inputs with only the HUD flag changed: full 240x160 indexed framebuffer and RGB555 palette after every advancing frame on both page parities, plus named selected-state/actor/economy/mission/trigger/save snapshots. Exercise cold and warm caches, camera/fog changes, unit and building selection, wallet and command updates, minimap edge dots, overlays, repeated pause and resume, text-box show/acknowledge, title/new game, save/fresh-load and result/retry on both pages. Include deterministic poisoned-page HOST tests and actual Z9/Z10 guest custom and campaign traces where available, with meaningful busy and ordinary scenes. Record same-source maps, EWRAM/IWRAM guards, `.su` nested call chains and observed stack high-water separately; compare uninstrumented whole-frame cycles and worst frames. A missing actual guest scene is an explicit gap, not inferred from another product.
