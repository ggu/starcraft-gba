# StarCraft 64-derived GBA adaptation

The optional GBA profile imports Wasteland's map and selected graphics from a verified USA N64 ROM into this project's smaller RTS engine. It is a mission adaptation; it does not run, recompile, or reproduce the N64 engine, and it is not a complete StarCraft port or matching decompilation.

## Current campaign profiles

The current separate-ROM campaign targets are Terran 1–10, Zerg 1–6, and
Protoss 1–5. The canonical Zerg target is the versioned Z6 ROM
`build/StarCraft-Zerg-Z6-GBA.gba`, with game code `SCZ6`, save generation 32
and a separate `.local/play/zerg-z6` directory. The explicit legacy `zerg-z4`
target keeps `build/StarCraft-Zerg-Z4-GBA.gba`, `SCZ4` and
`.local/play/zerg-z4`. The explicit legacy `zerg-z3` target keeps
`build/StarCraft-Zerg-GBA.gba`, save code `SCZ3`, and `.local/play/zerg`;
the versioned Z3 filenames are aliases to those legacy outputs. Saves are not
converted between identities. Z4's normal-input controller win and cold-load
evidence are documented in the [campaign guide](RACE-CAMPAIGNS.md); the
generic split save-report checker does not validate Z4 campaign-model
continuity. Current qualification and measured frame rates are summarized in
[Validation](VALIDATION.md).

## Prepare, build, and play

```sh
./dev sc64 prepare --rom "/path/to/StarCraft 64 ROM or ZIP" --profile wasteland
./dev sc64 build --profile wasteland
./dev sc64 test --profile wasteland
./dev sc64 play --profile wasteland
```

The optional preparation requires a user-supplied supported StarCraft 64 USA image and the pinned `sc64-maps` extractor. The wrapper can fetch that extractor from its public upstream and checks out the recorded commit. It accepts a USA `.z64`, `.v64`, `.n64`, or ZIP containing exactly one 32 MiB N64 image, normalizes byte order, and verifies SHA-1 `a36d91b5aac7bb95df0d7de5f9814f5270e25c2b`. ROMs and converted data remain local under ignored `.local/` and `build/` directories. The project does not distribute them.

The default original-art skirmish builds with `./dev build` and `./dev test` without ROMs, original assets, or research checkouts. The unified public profile, with all six missions, is described in [SC64-UNIFIED.md](SC64-UNIFIED.md).

## Imported scenario

The pinned extractor enumerates 96 scenarios. Wasteland is BOLT `008/00A`, with internal CHK name `T1) Wasteland`. The importer records the 64×64 terrain, unit placements, and trigger audit. The map contains the original bridges, river, cliffs, and roads, with 1,150 source terrain IDs deduplicated to 938 rendered GBA tiles. Ten static sprite snapshots are converted locally: Marine, SCV, Raynor's Vulture, Zergling, Command Center, Supply Depot, Barracks, and three mineral-field types. All imported graphics remain local.

The initial placements include five Marines, five SCVs, Raynor's Vulture, 23 Zerglings, one Command Center, one Supply Depot, and ten mineral fields; editor start markers are retained in the audit and omitted from play. The mission begins in the northwest. Raynor is near the centre, and the existing base and minerals are farther south. Workers seek minerals automatically, so escort them while advancing toward the outpost.

The nine source trigger records inform selected objectives: rescue Raynor, own a Barracks and ten Marines, keep Raynor alive, and the applicable loss conditions. These are implemented as mission-specific rules, not as a general CHK trigger interpreter. A controller-driven route is recorded in [SC64_WALKTHROUGH.md](SC64_WALKTHROUGH.md).

## Controls

- D-pad moves the cursor; hold R for faster movement and camera scrolling.
- A selects a unit or issues its contextual order. A single tap acts immediately. Double-tap A on a friendly unit to select matching living units currently on screen; offscreen units are excluded. Building selection, orders, production queues, and building placement retain their contextual actions.
- Tap L to cycle friendly units. Hold L with the D-pad to drag a selection box; release L to select living friendlies inside. B cancels and preserves the previous selection; A is ignored during the drag. Committing a box cancels pending move/build mode.
- Tap R to select the combat group. Holding R with D-pad movement speeds cursor and box movement; tap R after releasing L to select the group. With a Barracks selected, R cycles training type.
- B opens commands, including Move, Attack Move, and construction. Select an SCV before placing a building. Select a Barracks and press A to queue Marines. L cancels its oldest queued unit.
- Start or Select pauses. A resumes, B saves, L loads, and R restarts. The title screen uses A to begin and B to load.

## Fidelity limits and validation

The GBA interface and selection/health markers are authored. Imported unit graphics use a reduced 224-colour world palette and one static frame per sprite; prepared race builds also include source-derived building construction animations. Directional unit animation, transmissions, and cinematics are not included. Imported StarCraft 64 sound effects, unit responses and music play when the optional audio bank is prepared ([Development](DEVELOPMENT.md#optional-starcraft-64-sound-effects-and-music)). Movement uses a coarse 16-pixel path grid derived from VF4 walk flags; it does not reproduce the original sub-tile pathfinder, elevation combat, sight, or collision footprints. Enemy behavior, combat, and the supported Terran roster are reduced. Unsupported initial records are counted rather than silently truncated.

In the recorded 24,351-input mGBA replay, the ARM build averaged 29.82 updates per second and met nominal two-display-frame pacing on 99.8% of updates. Route creation, saves, restarts, loads, and interface changes can hitch. This is one controller-driven winning route, not proof of exhaustive strategy balance. Physical GBA SP/EverDrive testing remains pending. See [VALIDATION.md](VALIDATION.md) for reproducible checks and current results.

`tools/sc64_import.py`, `tools/sc64_assets.py`, and `tools/sc64_sprites.py` write local audit data, converted assets, headers, and previews. `make test-sc64` generates a controller-input trace; `python3 tools/sc64_replay.py` replays it against the ARM ROM in mGBA and checks gameplay checkpoints, victory, and SRAM.
